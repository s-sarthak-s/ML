Module 06 · How models work

The transformer, one block at a time

Llama, Qwen, Mistral, Gemma and GPT-2 are all the same machine: an embedding table, one block repeated anywhere from a dozen to more than a hundred times, and a projection back to the vocabulary. Once you can draw that block and count what's inside it, a model card stops being a list of magic numbers. You can read "32 layers, 8 KV heads, d_ff 14336" and know the parameter count, the KV cache size, and where the FLOPs go.

The decoder-only stack

A decoder-only transformer does one job. Given tokens \(t_1, \dots, t_T\), it produces, at every position, a probability distribution over the next token. Position 5's output is a guess for token 6. During training all \(T\) guesses are scored at once; during generation you only use the last one.

The pipeline is short. Token ids become vectors by looking up rows of an embedding table (Module 05). Those vectors then pass through \(N\) identical blocks. Each block has two sub-layers, and each sub-layer follows the same recipe: normalize a copy of the input, compute something, add the result back. After the last block, one more normalization and a matrix multiply turn each vector into \(V\) logits, one per vocabulary entry.

Attention · communication

Tokens read from each other

Each position builds a weighted average of information from earlier positions. This is how "it" finds out which noun it refers to. It's the only operation in the network whose output at position \(t\) depends on other positions.

MLP · computation

Each token thinks alone

A two-layer network applied independently to every position. It holds most of the parameters (about 70% in Llama-3-8B) and is where much of the model's stored knowledge appears to live.

Definition · decoder-only

The original Transformer (Vaswani et al., 2017) was built for translation: an encoder read the source sentence with full bidirectional attention, and a decoder generated the target while also attending to the encoder's output. GPT-style language models keep only the decoder stack, drop that cross-attention, and keep the causal mask so each position sees only its past. "Transformer" in this course means this decoder-only variant.

Think first: in Llama-3-8B, which component holds the most parameters?
The MLPs. Each layer's SwiGLU MLP has \(3 \times 4096 \times 14336 \approx 176\)M parameters against about 42M for attention, so across 32 layers the MLPs hold 5.64B of the 8.03B total. Embeddings and the LM head together are 1.05B, and attention is only 1.34B. You'll verify every one of those numbers with the calculator in §06.11.

The residual stream

Look again at the figure and follow the left-hand line. The input to block 1 is the embedding. Its output is the embedding plus whatever attention added, plus whatever the MLP added. Block 2 starts from that sum. Nothing ever replaces the vector; each sub-layer only adds a correction to it.

$$\htmlClass{t2}{x'} = \htmlClass{t1}{x} + \htmlClass{t3}{\text{Attn}}\big(\htmlClass{t5}{\text{Norm}_1}(\htmlClass{t1}{x})\big), \qquad \htmlClass{t6}{x''} = \htmlClass{t2}{x'} + \htmlClass{t4}{\text{MLP}}\big(\htmlClass{t5}{\text{Norm}_2}(\htmlClass{t2}{x'})\big)$$
\(x\)
residual stream entering the block, shape \([B, T, d]\)
\(x'\)
stream after the attention sub-layer has added its output
Attn
causal multi-head self-attention (§06.3 to §06.7)
MLP
position-wise feed-forward network (§06.10)
Norm
RMSNorm (or LayerNorm), each with its own learned gain \(\gamma\)
\(x''\)
block output, which is the next block's \(x\)

In wordsEach sub-layer looks at a normalized copy of the stream, computes a change, and adds the change back. The stream itself is never normalized or overwritten inside the block.

Why it mattersThe plain \(x +\) path means the derivative of the output with respect to the input always contains an identity term. Gradients reach layer 1 of a 100-layer model without being squeezed through 120 nonlinearities, which is why these networks train at all.

This view explains several things you'll see in practice:

  • The logit lens works: applying the final norm and LM head to the stream after an intermediate layer often gives sensible next-token guesses that sharpen with depth. The stream is in roughly the same "language" throughout.
  • Dropping or skipping individual middle layers usually degrades a model gracefully instead of breaking it. That's the basis for layer pruning and early-exit experiments.
  • The stream has a fixed width \(d\). Every feature the model wants to carry between layers has to share those 4,096 dimensions, which is one reason interpretability researchers find features stored in overlapping directions rather than one per dimension.
Intuition

Picture a whiteboard per token. Attention lets a token copy notes from other tokens' whiteboards onto its own. The MLP lets it think about what's on its whiteboard and jot down conclusions. No one ever erases the board; they just keep writing.

Self-attention: queries, keys, values

Take the sentence "The cat sat on the mat because it was tired." To predict what comes after "it", the model needs to know that "it" means the cat. That information sits at another position. Attention is the mechanism that fetches it.

Each token's stream vector is projected three ways:

  • a query \(q\), roughly "what am I looking for?" (for "it": a singular, animate noun earlier in the sentence);
  • a key \(k\), "what can I be found by?" (for "cat": I'm a singular animate noun);
  • a value \(v\), "what I hand over if you pick me" (for "cat": the features that say what a cat is).

The query is compared with every key by a dot product. High score, high weight. The output is the weighted average of the values. It's a dictionary lookup where the match is soft: instead of returning the one entry whose key equals the query, it returns a blend of all entries, weighted by similarity.

$$\htmlClass{t1}{Q} = \htmlClass{t4}{X}\,\htmlClass{t5}{W_Q}, \qquad \htmlClass{t2}{K} = \htmlClass{t4}{X}\,\htmlClass{t5}{W_K}, \qquad \htmlClass{t3}{V} = \htmlClass{t4}{X}\,\htmlClass{t5}{W_V}$$
\(X\)
normalized residual stream for one sequence, shape \([T \times d]\): one row per token
\(W_Q, W_K, W_V\)
learned matrices, \([d \times d_k]\) for Q and K and \([d \times d_v]\) for V. The same matrices are used at every position
\(Q\)
queries, \([T \times d_k]\): row \(i\) is what token \(i\) is looking for
\(K\)
keys, \([T \times d_k]\): row \(j\) is how token \(j\) can be found
\(V\)
values, \([T \times d_v]\): row \(j\) is what token \(j\) contributes when attended to

In wordsThree ordinary matrix multiplies turn each token's vector into a question, a label, and a payload.

Why it mattersKeys and values depend only on their own token and position, never on the query. So during generation you can compute them once per token and keep them: that's the KV cache (Module 08). Queries are needed only for the newest token.

Definition · self- vs cross-attention

Self-attention takes Q, K and V from the same sequence. Cross-attention takes Q from one sequence and K, V from another, as in encoder-decoder translation models or some vision-language models where text queries attend to image features. Decoder-only LLMs use self-attention only.

Scaled dot-product attention

Stack all queries and all keys and the comparisons become one matrix multiply. Here is the whole operation, the single most important formula in this course:

$$\text{Attention}(\htmlClass{t1}{Q},\htmlClass{t2}{K},\htmlClass{t3}{V}) = \htmlClass{t6}{\text{softmax}}\!\left(\frac{\htmlClass{t1}{Q}\,\htmlClass{t2}{K}^{\top}}{\sqrt{\htmlClass{t4}{d_k}}} + \htmlClass{t5}{M}\right)\htmlClass{t3}{V}$$
\(Q\)
queries \([T \times d_k]\)
\(K^{\top}\)
keys transposed \([d_k \times T]\). \(QK^{\top}\) is \([T \times T]\): entry \((i, j)\) is \(q_i \cdot k_j\), how well token \(i\)'s query matches token \(j\)'s key
\(d_k\)
query/key dimension (the head dimension, 128 in most current models). Dividing by \(\sqrt{d_k}\) keeps the scores at unit scale
\(M\)
mask \([T \times T]\): 0 where attention is allowed, \(-\infty\) where it isn't (§06.5)
softmax
applied to each row separately, so each query's weights over the keys are positive and sum to 1
\(V\)
values \([T \times d_v]\). Weights \([T \times T]\) times \(V\) gives the output \([T \times d_v]\): one blended value per query

In wordsScore every query against every key, scale the scores down, block the forbidden ones, turn each row into probabilities, and use those probabilities to average the values.

Why it mattersThe \([T \times T]\) score matrix is why attention's cost grows quadratically with context length, while everything else in the block grows linearly.

Why divide by \(\sqrt{d_k}\)

Suppose the entries of \(q\) and \(k\) are independent with mean 0 and variance 1, which is roughly the situation at initialization. A dot product is a sum of \(d_k\) such products, and variances of independent terms add:

$$\htmlClass{t1}{\mathbf{q}}\cdot\htmlClass{t2}{\mathbf{k}} = \sum_{i=1}^{\htmlClass{t3}{d_k}} q_i\,k_i, \qquad \mathbb{E}[\mathbf{q}\cdot\mathbf{k}] = 0, \qquad \operatorname{Var}[\mathbf{q}\cdot\mathbf{k}] = \htmlClass{t3}{d_k}$$
\(\mathbf{q}\)
a query vector, entries assumed mean 0, variance 1
\(\mathbf{k}\)
a key vector, independent of \(\mathbf{q}\), same assumption
\(d_k\)
number of terms in the sum. Each \(q_i k_i\) has variance 1, so the sum has variance \(d_k\)

In wordsThe typical size of a raw score grows like \(\sqrt{d_k}\). With \(d_k = 128\) that's about 11. Dividing by \(\sqrt{d_k}\) brings the standard deviation back to 1, whatever the head size.

Why it mattersSoftmax only cares about differences between scores. If scores differ by 20, \(e^{20}\) makes one weight about 1 and the rest about 0. A saturated softmax has gradient \(\partial p_i/\partial z_j = p_i(\delta_{ij} - p_j) \approx 0\), so attention stops learning before it starts.

Think first: softmax is shift-invariant. Is it scale-invariant?
No. Adding a constant to every score changes nothing, because it cancels in the ratio \(e^{z_i}/\sum_j e^{z_j}\). Multiplying every score by a constant is the same as changing the softmax temperature: multiply by 10 and a gentle preference becomes a hard choice. That's why the \(1/\sqrt{d_k}\) factor matters and why you can't just leave it out and hope the network compensates.
Pitfall

Writing your own attention and scaling by \(1/d_k\) instead of \(1/\sqrt{d_k}\), or forgetting the scale, produces a model that trains, just badly, so the bug can hide for days. Some families deliberately use a different constant (μP-style parameterizations use \(1/d_k\); a few models set it in the config). When porting weights, take the scale from the reference implementation, not from memory.

Causal masking

Training feeds the model a whole sequence and asks for a next-token prediction at every position at once. If position 7 could attend to position 8, it could simply read the answer. The mask forbids that:

$$\htmlClass{t1}{M_{ij}} = 0 \;\text{ if }\; \htmlClass{t3}{j} \le \htmlClass{t2}{i}, \qquad \htmlClass{t1}{M_{ij}} = -\infty \;\text{ if }\; \htmlClass{t3}{j} \gt \htmlClass{t2}{i}$$
\(M_{ij}\)
value added to score \((i, j)\) before the softmax
\(i\)
query position: the row, the token doing the looking
\(j\)
key position: the column, the token being looked at

In wordsUpper triangle (the future) gets \(-\infty\), so \(e^{-\infty} = 0\) and those weights vanish. The diagonal and everything below stay as computed.

Why it mattersThe mask is what makes training parallel. One forward pass over a 4,096-token sequence yields 4,096 honest next-token predictions, each computed exactly as it would be at generation time.

Think first: during generation with a KV cache, the newest token's query is scored against all cached keys. Do you still need a mask?
Not for that step. Every cached key is from an earlier position, so the single row of the mask is all zeros. The mask matters during training and prefill, when many query positions are processed at once, and for padding when sequences of different lengths share a batch. Inference engines exploit this: decode kernels typically skip the mask entirely.
Pitfall · padding and NaN

If a row is masked everywhere (a padding query whose keys are all padding), softmax computes \(0/0\) and returns NaN, which then spreads through the batch. Use a large finite negative number instead of \(-\infty\), or make sure every query can see at least one key, usually itself. Also check padding side: decoder-only models generating in batches want left padding so the last position is a real token.

MLE angle · the \(T \times T\) matrix is never stored

For Llama-3-8B at \(T = 8192\), one layer's score tensor is \(32 \times 8192 \times 8192 \approx 2.1\)B numbers, about 4 GiB in bf16. FlashAttention (Dao et al., 2022) computes attention in tiles that fit in on-chip SRAM, keeping a running max and sum for the softmax, so the full matrix never touches GPU memory. The math is identical; the extra memory drops from quadratic to linear in \(T\), and reads and writes to GPU memory fall several-fold. F.scaled_dot_product_attention dispatches to a fused kernel like this when it can.

Multi-head attention

One softmax gives each query one weighting over the past. But a token usually needs several things at once: "it" wants its antecedent, the previous word, and maybe the verb it belongs to. Multi-head attention runs \(h\) smaller attentions in parallel, each with its own projections, and concatenates the results.

$$\text{MultiHead}(\htmlClass{t1}{X}) = \text{Concat}(\htmlClass{t2}{\text{head}_1},\dots,\htmlClass{t2}{\text{head}_{h}})\,\htmlClass{t3}{W_O}, \qquad \htmlClass{t2}{\text{head}_i} = \text{Attention}\big(\htmlClass{t1}{X}W_Q^{(i)},\; \htmlClass{t1}{X}W_K^{(i)},\; \htmlClass{t1}{X}W_V^{(i)}\big), \qquad \htmlClass{t4}{d_{\text{head}}} = d / \htmlClass{t5}{h}$$
\(X\)
normalized stream \([T \times d]\)
\(\text{head}_i\)
output of the \(i\)-th attention, \([T \times d_{\text{head}}]\), with its own \([d \times d_{\text{head}}]\) projections
\(W_O\)
output projection \([h\,d_{\text{head}} \times d]\): mixes the heads' results and writes them back into the stream
\(d_{\text{head}}\)
per-head dimension. Llama-3-8B: \(4096 / 32 = 128\)
\(h\)
number of heads

In wordsCut the model width into \(h\) slices, run attention separately in each slice, glue the slices back together, and mix them with one more matrix.

Why it mattersIt costs nothing extra. In practice \(W_Q\) is a single \([d \times d]\) matrix whose output is reshaped into \(h\) pieces, so parameters and matmul FLOPs are the same as one big head. You get \(h\) independent attention patterns for free.

What attention heads end up doing

Nobody assigns heads their jobs, but some recognisable ones appear reliably. Previous-token heads put almost all their weight on position \(i-1\). Many heads in many models dump most of their weight on the first token whatever it is; this "attention sink" seems to act as a no-op default when a head has nothing useful to fetch (Xiao et al., 2023). The best-studied circuit is the induction head.

Elhage et al. (2021) found induction heads in small attention-only models, and Olsson et al. (2022) argued that they account for a large share of in-context learning in bigger ones. They form fairly abruptly early in training, visible as a bump in the loss curve, and their appearance coincides with the model getting much better at using earlier context. Treat the specific story with some care: plenty of heads don't have a clean description, and Michel et al. (2019) showed that many heads can be pruned at test time with little loss.

Sharing keys and values: MQA and GQA

Standard multi-head attention (MHA) gives every query head its own key and value heads. During generation, every past token's K and V for every head and layer sit in the KV cache, and every decode step reads all of it. At long contexts that cache, not the weights, becomes the memory and bandwidth bottleneck.

The fix is to let several query heads share one K/V head. Multi-query attention (MQA, Shazeer, 2019) shares a single K/V head across all query heads. Grouped-query attention (GQA, Ainslie et al., 2023) is the compromise most current models use: query heads are split into groups, and each group shares a K/V head.

$$\htmlClass{t1}{\text{KV bytes/token}} = 2 \times \htmlClass{t2}{L} \times \htmlClass{t3}{n_{kv}} \times \htmlClass{t4}{d_{\text{head}}} \times \htmlClass{t5}{b}$$
KV bytes/token
cache memory added by every token of context. The leading 2 is one K plus one V
\(L\)
number of layers; each layer has its own cache
\(n_{kv}\)
number of KV heads: \(h\) for MHA, \(h/g\) for GQA with groups of \(g\), 1 for MQA
\(d_{\text{head}}\)
head dimension
\(b\)
bytes per number: 2 for bf16, 1 for an fp8 cache

In wordsLlama-3-8B: \(2 \times 32 \times 8 \times 128 \times 2 = 131{,}072\) bytes, 128 KiB per token, so 1 GiB per 8K tokens of context. With full MHA (32 KV heads) it would be 512 KiB per token, four times as much.

Why it mattersGQA barely changes parameter count (\(W_K\) and \(W_V\) shrink from \([d \times d]\) to \([d \times n_{kv} d_{\text{head}}]\)) but cuts the dominant cost of long-context serving. Module 08 builds on this formula.

On quality: Ainslie et al. reported GQA close to MHA quality at close to MQA speed, and showed that an existing MHA checkpoint can be "uptrained" into GQA by mean-pooling its K/V heads and continuing training briefly. MQA saves more but tends to cost more quality, and it complicates tensor parallelism because one K/V head can't be split across GPUs. DeepSeek-V2 (2024) went further with multi-head latent attention, which caches a compressed latent vector per token and reconstructs K and V from it.

Pitfall · which query heads share a KV head?

Conventionally query heads \(0..g-1\) share KV head 0, the next \(g\) share KV head 1, and so on. In PyTorch that's k.repeat_interleave(g, dim=1). Using k.repeat(1, g, 1, 1) instead tiles the heads in the wrong order, and a pretrained model will produce fluent-looking garbage. Recent PyTorch versions (2.5+) also accept enable_gqa=True in F.scaled_dot_product_attention, which handles it without materializing the copies.

Where position comes from: sinusoids and RoPE

Nothing in attention so far knows about order. Scores are dot products between vectors, and a weighted sum doesn't care which slot an item came from. Shuffle the input tokens and, apart from the causal mask, every output shuffles the same way. "Dog bites man" and "man bites dog" would get the same representations. Position information has to be injected.

Absolute positions: sinusoidal and learned

The original Transformer added a fixed vector to each token's embedding depending on its position:

$$\htmlClass{t1}{PE}_{(\htmlClass{t2}{p},\,2i)} = \sin\!\left(\frac{\htmlClass{t2}{p}}{10000^{\,2\htmlClass{t3}{i}/\htmlClass{t4}{d}}}\right), \qquad \htmlClass{t1}{PE}_{(\htmlClass{t2}{p},\,2i+1)} = \cos\!\left(\frac{\htmlClass{t2}{p}}{10000^{\,2\htmlClass{t3}{i}/\htmlClass{t4}{d}}}\right)$$
\(PE\)
positional vector added to the token embedding at the input
\(p\)
position of the token in the sequence: 0, 1, 2, …
\(i\)
index of the sin/cos pair, \(0 \le i \lt d/2\). Low \(i\) means a fast oscillation, high \(i\) a slow one
\(d\)
model width

In wordsEach pair of dimensions is a clock hand turning at its own speed. The fastest completes a cycle every \(2\pi \approx 6\) positions, the slowest every \(2\pi \times 10000\). Together the hands give every position a unique fingerprint, like reading hours, minutes and seconds.

GPT-2 instead learned a table of 1,024 position vectors (786K parameters for \(d = 768\)). Learned tables work well but can't represent position 1,025 at all. Both schemes are absolute: they tell the model "you are at position 517", while language mostly cares about "that word was 3 tokens ago".

Rotary position embedding (RoPE)

RoPE (Su et al., 2021), used by Llama, Qwen, Mistral, Gemma and most other open models, doesn't add anything to the embedding. Instead, inside every attention layer, it rotates each query and key by an angle proportional to its position, just before the dot product. The head dimension is treated as \(d/2\) pairs, and each pair is rotated like a 2D vector:

$$\htmlClass{t1}{\tilde q}_{2i} = \htmlClass{t2}{q}_{2i}\cos(\htmlClass{t3}{m}\htmlClass{t4}{\theta_i}) - \htmlClass{t2}{q}_{2i+1}\sin(\htmlClass{t3}{m}\htmlClass{t4}{\theta_i}), \qquad \htmlClass{t1}{\tilde q}_{2i+1} = \htmlClass{t2}{q}_{2i}\sin(\htmlClass{t3}{m}\htmlClass{t4}{\theta_i}) + \htmlClass{t2}{q}_{2i+1}\cos(\htmlClass{t3}{m}\htmlClass{t4}{\theta_i})$$ $$\htmlClass{t4}{\theta_i} = \htmlClass{t5}{\text{base}}^{-2i/\htmlClass{t6}{d}}, \qquad i = 0, 1, \dots, d/2 - 1$$
\(q\)
query (or key) for one head, before rotation
\(\tilde q\)
rotated query; keys get exactly the same treatment with their own position
\(m\)
the token's position
\(\theta_i\)
rotation speed of pair \(i\), radians per position: 1 for \(i = 0\), tiny for the last pair
base
10,000 in the original paper and Llama 2; 500,000 in Llama 3. A larger base slows every clock, which helps long context
\(d\)
here the head dimension (128 for Llama-3-8B), since RoPE is applied per head

In wordsRotate pair \(i\) of the vector by \(m\theta_i\). It's the same set of clock speeds as the sinusoidal encoding, but used to turn the vector rather than added to it.

The payoff comes when a rotated query meets a rotated key. Writing \(R_m\) for "rotate every pair by \(m\theta_i\)":

$$\big\langle \htmlClass{t1}{R_m}\htmlClass{t3}{q},\; \htmlClass{t2}{R_n}\htmlClass{t4}{k} \big\rangle = \htmlClass{t3}{q}^{\top}\htmlClass{t1}{R_m}^{\top}\htmlClass{t2}{R_n}\,\htmlClass{t4}{k} = \htmlClass{t3}{q}^{\top}\htmlClass{t5}{R_{n-m}}\,\htmlClass{t4}{k}$$
\(R_m\)
rotation for the query's position \(m\). Rotations are orthogonal, so \(R_m^{\top} = R_{-m}\)
\(R_n\)
rotation for the key's position \(n\)
\(q\)
query content
\(k\)
key content
\(R_{n-m}\)
rotating by \(-m\) then \(+n\) is one rotation by \(n - m\): only the offset survives

In wordsTurn the query by its position and the key by its position, and the angle between them depends only on how far apart they are. Positions 10 and 3 give exactly the same score as 1,010 and 1,003.

Why it mattersAttention scores become a function of content and relative distance, with no learned parameters. Values are not rotated, so position steers where a head looks without changing what it copies.

Two RoPE layouts

The formula pairs adjacent dimensions \((2i, 2i{+}1)\), as in Meta's original Llama code. Hugging Face and GPT-NeoX pair dimension \(i\) with \(i + d/2\) ("rotate half"). The two are equivalent if the \(W_Q\) and \(W_K\) columns are permuted to match, which is exactly what the HF Llama conversion script does. Mix a checkpoint from one convention with code from the other and the model loads without error and outputs nonsense.

Long-context extensions mostly work by changing the clocks: raising the base, or scaling down the angles for the slow pairs so that positions beyond the training length map onto angles the model has seen (position interpolation, NTK-aware scaling, YaRN). Module 08 covers them. Other relative schemes exist, such as ALiBi (Press et al., 2021), which adds a distance-proportional penalty to the scores, but RoPE is the default today.

Normalization: LayerNorm, RMSNorm, and where they sit

Each sub-layer reads a normalized copy of the stream. Normalization is per token, across that token's \(d\) features. It has nothing to do with the batch, unlike BatchNorm in vision models. It keeps the scale of what a sub-layer sees roughly fixed, whatever has accumulated in the stream so far.

$$\text{LN}(\htmlClass{t1}{x}) = \htmlClass{t4}{\gamma} \odot \frac{\htmlClass{t1}{x} - \htmlClass{t2}{\mu}}{\sqrt{\htmlClass{t3}{\sigma^2} + \htmlClass{t6}{\epsilon}}} + \htmlClass{t5}{\beta}, \qquad \htmlClass{t2}{\mu} = \tfrac{1}{d}\textstyle\sum_j x_j, \qquad \htmlClass{t3}{\sigma^2} = \tfrac{1}{d}\textstyle\sum_j (x_j - \mu)^2$$
\(x\)
one token's vector, \(d\) numbers
\(\mu\)
mean of its features
\(\sigma^2\)
variance of its features
\(\gamma\)
learned per-feature gain, \(d\) parameters
\(\beta\)
learned per-feature bias, \(d\) parameters
\(\epsilon\)
small constant (around \(10^{-5}\)) to avoid division by zero

In wordsShift the vector to mean 0, scale it to variance 1, then let the model choose its own scale and offset per feature.

$$\text{RMSNorm}(\htmlClass{t1}{x}) = \htmlClass{t4}{\gamma} \odot \frac{\htmlClass{t1}{x}}{\htmlClass{t2}{\text{RMS}(x)}}, \qquad \htmlClass{t2}{\text{RMS}(x)} = \sqrt{\tfrac{1}{d}\textstyle\sum_{j=1}^{d} x_j^2 + \htmlClass{t3}{\epsilon}}$$
\(x\)
one token's vector
\(\text{RMS}(x)\)
root-mean-square: the vector's typical magnitude, with no mean subtracted
\(\epsilon\)
stability constant (Llama 3 uses \(10^{-5}\))
\(\gamma\)
learned gain; there's no \(\beta\)

In wordsJust rescale the vector to unit RMS. No centring, no bias.

Why it mattersZhang & Sennrich (2019) found the re-centring contributes little. RMSNorm needs one reduction instead of two and half the parameters, and almost every recent LLM uses it.

Pre-norm vs post-norm

Where the norm sits matters more than which norm it is. The 2017 Transformer put it after the residual add. GPT-2 moved it to the input of each sub-layer and added one final norm at the end of the stack. Nearly everything since has followed.

Xiong et al. (2020) showed that post-norm transformers have large gradients near the output at initialization and need a careful learning-rate warmup to train, while pre-norm ones are well behaved. Post-norm can reach slightly better quality when it does train, which is why some recent models add a norm on the sub-layer output before it is added back (Gemma 2 and OLMo 2 do variants of this) while keeping the residual path itself clean.

Pitfall · compute norms in fp32

The sum of squares over 4,096 or 8,192 features can lose precision or overflow in fp16. Reference implementations upcast to fp32 inside the norm and cast back afterwards. The code at the end of this module does the same.

The MLP: GELU and SwiGLU

The MLP is applied to each position independently: same weights, no communication. The classic version (GPT-2, BERT) expands the vector to \(d_{ff} = 4d\), applies a nonlinearity, and projects back: \(\text{MLP}(x) = \text{GELU}(xW_1 + b_1)\,W_2 + b_2\), where \(\text{GELU}(z) = z\,\Phi(z)\) is a smooth ReLU (Hendrycks & Gimpel, 2016). That's \(2 \times d \times 4d = 8d^2\) parameters per layer, twice what attention has.

Geva et al. (2021) offered a useful picture: rows of \(W_1\) act like keys that detect patterns in the input, and the matching rows of \(W_2\) are values written to the stream when the pattern fires. A big share of factual recall seems to happen in these layers.

Modern models use a gated MLP instead. One projection is passed through an activation and used to gate a second projection, elementwise:

$$\text{SwiGLU}(\htmlClass{t1}{x}) = \big(\htmlClass{t5}{\text{SiLU}}(\htmlClass{t1}{x}\,\htmlClass{t2}{W_1}) \odot \htmlClass{t1}{x}\,\htmlClass{t3}{W_3}\big)\,\htmlClass{t4}{W_2}, \qquad \htmlClass{t5}{\text{SiLU}}(z) = z\,\sigma(z), \qquad \htmlClass{t6}{d_{ff}} \approx \tfrac{8}{3}\,d$$
\(x\)
normalized stream vector \([d]\)
\(W_1\)
"gate" projection \([d \times d_{ff}]\) (gate_proj in HF)
\(W_3\)
"up" projection \([d \times d_{ff}]\) (up_proj)
\(W_2\)
"down" projection \([d_{ff} \times d]\) (down_proj)
SiLU
also called Swish: \(z\) times its sigmoid. Smooth, slightly negative for small negative \(z\)
\(d_{ff}\)
hidden width. \(8/3\) keeps the parameter count equal to a \(4d\) GELU MLP: \(3 \times d \times \tfrac{8}{3}d = 8d^2\)

In wordsCompute two \(d_{ff}\)-wide projections, squash one of them, multiply the two elementwise so one acts as a learned per-dimension on/off switch for the other, then project back to \(d\).

Why it mattersShazeer (2020) found GLU variants gave better quality than plain GELU/ReLU MLPs at equal parameters and compute. The 3 matrices are why parameter formulas for Llama-style models have \(3\,d\,d_{ff}\) rather than \(2\,d\,d_{ff}\).

The \(8/3\) rule is a starting point, not law. Llama 1 7B used \(d_{ff} = 11008 \approx 2.69d\) (\(8/3 \times 4096\) rounded up to a multiple of 256). Llama-3-8B uses 14,336, which is \(3.5d\), and Llama-3-70B uses \(28672 = 3.5 \times 8192\). Always read \(d_{ff}\) from the config.

Think first: why is the MLP applied per position instead of mixing positions like attention?
Because it doesn't need to. Attention already moved whatever information this position needs onto its stream. Keeping the MLP per-position means its cost is linear in \(T\), it parallelizes perfectly across tokens, and the same weights work at any sequence length. The split is clean: attention moves information, the MLP processes it.

Counting parameters and FLOPs

You now know every matrix in the model, so you can count them. Start with the classic GPT-style block (MHA, \(4d\) GELU MLP, biases ignored):

$$\htmlClass{t1}{N} \approx \htmlClass{t2}{L}\,\big(\underbrace{\htmlClass{t3}{4d^2}}_{\text{attention}} + \underbrace{\htmlClass{t4}{8d^2}}_{\text{MLP}}\big) = 12\,\htmlClass{t2}{L}\,\htmlClass{t5}{d}^2$$
\(N\)
non-embedding parameters
\(L\)
number of layers
\(4d^2\)
\(W_Q, W_K, W_V, W_O\), each \([d \times d]\)
\(8d^2\)
\(W_1\) \([d \times 4d]\) plus \(W_2\) \([4d \times d]\)
\(d\)
model width

In wordsEach layer costs about twelve \(d \times d\) matrices. GPT-2 small: \(12 \times 12 \times 768^2 = 84.9\)M, against an exact non-embedding count of 85.1M.

Modern models break the "4" and the "8": GQA shrinks \(W_K\) and \(W_V\), and SwiGLU has three matrices with a non-standard \(d_{ff}\). The exact count for a Llama-style layer (RMSNorm, no biases, \(h \cdot d_{\text{head}} = d\)) is:

$$\htmlClass{t1}{P_{\text{layer}}} = \underbrace{2d^2 + 2\,d\,\htmlClass{t2}{n_{kv}}\,\htmlClass{t3}{d_{\text{head}}}}_{W_Q,\,W_O \;+\; W_K,\,W_V} + \underbrace{3\,d\,\htmlClass{t4}{d_{ff}}}_{\text{SwiGLU}} + \underbrace{2d}_{\text{norms}}, \qquad \htmlClass{t5}{N_{\text{total}}} = L \cdot \htmlClass{t1}{P_{\text{layer}}} + \underbrace{\htmlClass{t6}{V}\,d}_{\text{embedding}} + \underbrace{\htmlClass{t6}{V}\,d}_{\text{LM head if untied}} + d$$
\(P_{\text{layer}}\)
parameters in one block
\(n_{kv}\)
KV heads (8 for Llama-3-8B and -70B)
\(d_{\text{head}}\)
head dimension, so \(W_K\) and \(W_V\) are \([d \times n_{kv} d_{\text{head}}]\)
\(d_{ff}\)
MLP hidden width
\(N_{\text{total}}\)
everything, including the final norm's \(d\)
\(V\)
vocabulary size. With tied embeddings the LM head reuses the embedding matrix and adds nothing

In wordsLlama-3-8B: \(2(4096^2) + 2(4096)(8)(128) + 3(4096)(14336) + 8192 = 218{,}112{,}000\) per layer. Times 32 is 6.98B; add \(2 \times 128256 \times 4096 = 1.05\)B for the embedding and LM head and you get 8,030,261,248, which matches the published model exactly.

FLOPs per token

Every weight in a matmul is used once per token for one multiply and one add. That gives the most useful rule of thumb in LLM systems, plus a correction for attention over the context:

$$\htmlClass{t1}{C_{\text{fwd}}} \approx 2\,\htmlClass{t2}{N} + 4\,\htmlClass{t3}{L}\,\htmlClass{t4}{T}\,\htmlClass{t5}{d}$$
\(C_{\text{fwd}}\)
floating-point operations to run one token forward
\(N\)
parameters that take part in matmuls: all layers plus the LM head. The input embedding is a lookup and costs nothing
\(L\)
layers
\(T\)
number of earlier tokens this token attends to (its context length)
\(d\)
total query width \(h \cdot d_{\text{head}}\), usually equal to \(d\). GQA does not reduce this term

In words2 FLOPs per parameter, plus, in each layer, \(2Td\) for \(q \cdot K^{\top}\) and \(2Td\) for weights \(\times V\).

Why it mattersFor short contexts the \(2N\) term dominates. Averaged over a causal training sequence of length \(T\), each token sees about \(T/2\) others, giving the \(2LTd\) term in Kaplan et al. (2020). Training costs about 3× forward (a backward pass is about twice a forward), which is where \(6N\) FLOPs per token comes from (Module 07).

Mixture of experts

A mixture-of-experts (MoE) layer replaces the single MLP with \(E\) parallel MLPs, the experts, and a small router that picks \(k\) of them for each token. Attention stays the same. The model gets many more parameters, but each token only pays compute for \(k\) experts.

$$\htmlClass{t1}{g}(x) = \text{softmax}\big(\text{TopK}(\htmlClass{t2}{x\,W_r},\; \htmlClass{t3}{k})\big), \qquad \htmlClass{t4}{y} = \sum_{i \in \text{TopK}} \htmlClass{t1}{g_i}(x)\; \htmlClass{t5}{E_i}(x)$$
\(x W_r\)
router logits: one score per expert from a tiny \([d \times E]\) matrix
\(k\)
experts used per token (2 in Mixtral; 8 of 256 routed experts in DeepSeek-V3)
\(g\)
gate weights: TopK sets every score outside the top \(k\) to \(-\infty\), so the softmax spreads weight over the chosen \(k\) only
\(E_i\)
expert \(i\), usually a SwiGLU MLP of the usual shape
\(y\)
layer output, added to the residual stream like a normal MLP's

In wordsScore all experts, keep the best \(k\), run only those, and blend their outputs by the renormalized scores.

Why it mattersParameters and compute come apart. Mixtral 8x7B (Jiang et al., 2024) has about 46.7B parameters but uses about 12.9B per token. DeepSeek-V3 has 671B and activates 37B.

  • Memory follows total parameters. Every expert has to be resident, since the next token may want any of them. Mixtral needs memory for 46.7B weights.
  • Compute follows active parameters. FLOPs per token are about \(2 \times\) active parameters, like a 13B dense model.
  • Bandwidth is in between. At batch 1, decode reads only the chosen experts' weights. At large batch, tokens spread over all experts and you're back to reading nearly everything every step.
  • Routers need balancing. Left alone, routers collapse onto a few favourite experts. Training adds a load-balancing loss (Shazeer et al., 2017; Fedus et al., 2021 for Switch Transformer) or a bias-adjustment scheme, and serving spreads experts across GPUs (expert parallelism).
Softmax before or after top-k

The formula takes the softmax over the top-\(k\) logits. Hugging Face's Mixtral code takes the softmax over all experts, picks the top \(k\), then renormalizes. That gives the same weights. Other designs differ for real: Switch Transformer uses \(k = 1\) and doesn't renormalize, and DeepSeek-V3 uses sigmoid scores plus an always-on shared expert. Read the modelling code before assuming.

Hands-on: build a block in PyTorch

1. RoPE, causal attention with GQA, and a Llama-style block

About 60 lines contain a real Llama-style block. The attention module has two paths: a manual one that spells out the formula from §06.4, and the fused F.scaled_dot_product_attention. Your first test is checking that they agree.


import math
import torch
import torch.nn as nn
import torch.nn.functional as F

def rope_cache(T, head_dim, base=10000.0, device=None):
    inv_freq = base ** (-torch.arange(0, head_dim, 2, device=device).float() / head_dim)  # theta_i, [hd/2]
    ang = torch.outer(torch.arange(T, device=device).float(), inv_freq)                   # [T, hd/2]: m * theta_i
    ang = torch.cat([ang, ang], dim=-1)                                                  # [T, hd] (rotate-half layout)
    return ang.cos(), ang.sin()

def rotate_half(x):
    x1, x2 = x.chunk(2, dim=-1)              # pairs dim i with dim i + hd/2 (HF / NeoX convention)
    return torch.cat([-x2, x1], dim=-1)

def apply_rope(x, cos, sin):                 # x: [B, heads, T, hd]
    T = x.shape[-2]
    return (x * cos[:T] + rotate_half(x) * sin[:T]).type_as(x)

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-5):
        super().__init__()
        self.eps, self.weight = eps, nn.Parameter(torch.ones(d))
    def forward(self, x):
        xf = x.float()                       # norm in fp32, then cast back
        return (xf * torch.rsqrt(xf.pow(2).mean(-1, keepdim=True) + self.eps)).type_as(x) * self.weight

class CausalSelfAttention(nn.Module):
    def __init__(self, d, n_heads, n_kv_heads):
        super().__init__()
        self.h, self.kv, self.hd = n_heads, n_kv_heads, d // n_heads
        self.wq = nn.Linear(d, n_heads * self.hd, bias=False)
        self.wk = nn.Linear(d, n_kv_heads * self.hd, bias=False)
        self.wv = nn.Linear(d, n_kv_heads * self.hd, bias=False)
        self.wo = nn.Linear(n_heads * self.hd, d, bias=False)

    def forward(self, x, cos, sin, manual=False):
        B, T, _ = x.shape
        q = self.wq(x).view(B, T, self.h, self.hd).transpose(1, 2)    # [B, h, T, hd]
        k = self.wk(x).view(B, T, self.kv, self.hd).transpose(1, 2)   # [B, kv, T, hd]
        v = self.wv(x).view(B, T, self.kv, self.hd).transpose(1, 2)
        q, k = apply_rope(q, cos, sin), apply_rope(k, cos, sin)       # position enters here, not in V
        g = self.h // self.kv                                         # GQA: each KV head serves g query heads
        k, v = k.repeat_interleave(g, dim=1), v.repeat_interleave(g, dim=1)
        if manual:
            att = (q @ k.transpose(-2, -1)) / math.sqrt(self.hd)      # [B, h, T, T]
            future = torch.ones(T, T, dtype=torch.bool, device=x.device).triu(1)
            att = att.masked_fill(future, float("-inf")).softmax(dim=-1)
            y = att @ v                                               # [B, h, T, hd]
        else:
            y = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        return self.wo(y.transpose(1, 2).reshape(B, T, self.h * self.hd))

class SwiGLU(nn.Module):
    def __init__(self, d, d_ff):
        super().__init__()
        self.w1 = nn.Linear(d, d_ff, bias=False)   # gate_proj
        self.w3 = nn.Linear(d, d_ff, bias=False)   # up_proj
        self.w2 = nn.Linear(d_ff, d, bias=False)   # down_proj
    def forward(self, x):
        return self.w2(F.silu(self.w1(x)) * self.w3(x))

class Block(nn.Module):
    def __init__(self, d, n_heads, n_kv_heads, d_ff):
        super().__init__()
        self.norm1, self.norm2 = RMSNorm(d), RMSNorm(d)
        self.attn = CausalSelfAttention(d, n_heads, n_kv_heads)
        self.mlp = SwiGLU(d, d_ff)
    def forward(self, x, cos, sin):
        x = x + self.attn(self.norm1(x), cos, sin)   # pre-norm, residual add
        return x + self.mlp(self.norm2(x))

2. Check it


import torch
from block import Block, rope_cache, rotate_half

torch.manual_seed(0)
d, h, kv, d_ff, T = 256, 8, 2, 688, 16
blk = Block(d, h, kv, d_ff)
x = torch.randn(2, T, d)
cos, sin = rope_cache(T, d // h)

# 1. fused and manual attention agree
hn = blk.norm1(x)
fast, slow = blk.attn(hn, cos, sin), blk.attn(hn, cos, sin, manual=True)
print("sdpa == manual:", torch.allclose(fast, slow, atol=1e-5))            # True

# 2. causality: changing a future token must not change earlier outputs
x2 = x.clone(); x2[:, -1] += 1.0
print("causal:", torch.allclose(blk(x, cos, sin)[:, :-1], blk(x2, cos, sin)[:, :-1], atol=1e-5))  # True

# 3. RoPE scores depend only on m - n
cos_l, sin_l = rope_cache(2048, 64)
q, k = torch.randn(64), torch.randn(64)
rot = lambda v, p: v * cos_l[p] + rotate_half(v) * sin_l[p]
print(float(rot(q, 10) @ rot(k, 3)), float(rot(q, 1010) @ rot(k, 1003)))  # equal up to float error

# 4. parameter count of one block: 2*d*d + 2*d*kv*(d//h) + 3*d*d_ff + 2*d
print(sum(p.numel() for p in blk.parameters()), 2*d*d + 2*d*kv*(d//h) + 3*d*d_ff + 2*d)

A batch of 2 sequences, 8 heads, 512 tokens, head dimension 64. What is the shape of the attention score tensor \(QK^{\top}\)?

  1. [2, 512, 64]
  2. [2, 8, 512, 64]
  3. [2, 8, 512, 512]
  4. [2, 512, 512, 64]
Each head scores every query against every key: [B, h, T, d_head] @ [B, h, d_head, T] = [B, h, T, T]. The head dimension is summed away in the dot product. [2, 8, 512, 64] is the shape of Q, K, V and the attention output.

You remove the \(1/\sqrt{d_k}\) factor from a model with \(d_k = 128\). What goes wrong at initialization?

  1. Raw scores have standard deviation around 11, so softmax saturates to nearly one-hot and its gradients nearly vanish
  2. Scores shrink toward 0, so attention becomes uniform
  3. Nothing: softmax is scale-invariant
  4. The matmul overflows bf16
A sum of 128 unit-variance products has variance 128, so std \(\sqrt{128} \approx 11.3\). Gaps of 20+ between scores make softmax pick one key, and \(p_i(\delta_{ij} - p_j) \approx 0\). Softmax is shift-invariant, not scale-invariant. bf16's range is fine; the problem is the softmax, not overflow.

A classic GPT-style model (MHA, \(4d\) GELU MLP) has \(d = 2048\) and \(L = 24\). Roughly how many non-embedding parameters does it have?

  1. ~0.6B
  2. ~1.2B
  3. ~2.4B
  4. ~4.8B
\(12 L d^2 = 12 \times 24 \times 2048^2 = 12 \times 24 \times 4.19\text{M} \approx 1.21\)B. Attention contributes \(4d^2\) and the MLP \(8d^2\) per layer. 0.6B would forget the MLP's second matrix or half the layers.

Llama-3-70B: 80 layers, 64 query heads, 8 KV heads, head dimension 128, bf16 cache. How much KV cache does each token add, and how does that compare with full MHA?

  1. 2.5 MiB, the same as MHA
  2. 160 KiB, 16× smaller
  3. 640 KiB, 4× smaller
  4. 320 KiB, 8× smaller
\(2 \times 80 \times 8 \times 128 \times 2 = 327{,}680\) bytes = 320 KiB. MHA would use 64 KV heads: 2.5 MiB per token. The saving is \(64/8 = 8\times\). A 32K-token context costs 10 GiB of cache instead of 80 GiB.

With RoPE, a query with content \(q\) at position 100 attending to a key with content \(k\) at position 90 produces score \(s\). The same \(q\) and \(k\) at positions 1,010 and 1,000?

  1. A larger score, because the angles are larger
  2. Exactly \(s\), up to floating-point rounding
  3. A smaller score, because rotations accumulate error
  4. \(-s\)
\(\langle R_m q, R_n k\rangle = q^{\top} R_{n-m} k\). Only \(n - m = -10\) matters, and it's the same in both cases. (Very large positions do lose some float precision in the angles, which is why implementations compute them in fp32.)

Why do SwiGLU models use \(d_{ff} \approx \tfrac{8}{3}d\) instead of the classic \(4d\)?

  1. SiLU is more expensive to compute than GELU
  2. It makes \(d_{ff}\) a power of two
  3. SwiGLU has three matrices, and \(3 \times d \times \tfrac{8}{3}d = 8d^2\) matches the \(2 \times d \times 4d\) of a GELU MLP
  4. Gating halves the number of activations that need storing
Adding a third matrix at the same width would cost 50% more parameters and FLOPs. Shrinking \(d_{ff}\) by 2/3 makes the comparison fair, which is how Shazeer (2020) compared variants. Real models then round to hardware-friendly sizes, and some go wider (Llama 3 uses 3.5d).

Mixtral 8x7B has about 46.7B parameters and uses about 12.9B per token (top-2 of 8 experts). Serving it at batch 1, which is true?

  1. You need memory for all ~46.7B parameters, but per-token compute is like a ~13B dense model
  2. You only need memory for the ~12.9B active parameters
  3. Per-token compute is like a 46.7B dense model, but memory is like 13B
  4. It runs 8 separate 7B models and takes a vote
Any token may route to any expert, so all experts stay resident. Each token runs attention plus only 2 expert MLPs per layer, so FLOPs are about \(2 \times 12.9\)B. "8x7B" is a name, not 8 full models: attention and embeddings are shared, which is why the total is 46.7B rather than 56B.
