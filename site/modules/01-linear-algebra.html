Module 01 · Foundations

Vectors & matrices: the shapes inside a model

Strip away the vocabulary and a forward pass through Llama-3-8B is one operation done over and over: multiply a matrix by a batch of vectors. That's about 15 billion floating-point operations per token, and at short context lengths nearly all of them happen inside matrix multiplications. This module builds that operation up from a single dot product, one symbol at a time, and shows where each piece sits in a real model.

~2.5 hoursprereqs: 00, high-school algebrahands-on: NumPy, PyTorch

By the end you can

  1. Read a shape like [B, T, d] and predict the output shape of any matmul, linear layer, or broadcast before running it.
  2. Compute a dot product, a norm, and a cosine similarity by hand, and say why attention scores and embedding search are built from them.
  3. Picture a 2×2 matrix as a transformation of the plane and read its determinant as an area scale.
  4. Count the FLOPs of a matrix multiply (\(2MNK\)) and the parameters of a linear layer, all the way up to Llama-3-8B's 8.03B total.
  5. Explain SVD and rank-\(k\) approximation well enough to see why LoRA's \(W_0 + BA\) trains under 1% of a matrix's parameters.
  6. Say why a GPU runs matrix–matrix products near peak but matrix–vector products far below it.

Scalars, vectors, matrices, tensors

A language model never sees words. A tokenizer (Module 05) turns text into integer IDs, and the very first thing the model does with an ID is look up a row in a big table of numbers. From that point on, everything is arrays of floating-point numbers, and the only thing that distinguishes one array from another is its shape.

Definition · The four objects

A scalar is a single number, like a loss of 2.31 or a learning rate of \(3\times10^{-4}\). Its shape is (). A vector is an ordered list of \(d\) numbers, written \(\mathbf{x}\in\mathbb{R}^d\) ("x is in R-d"), with shape [d]. A matrix is a grid with \(m\) rows and \(n\) columns, \(W\in\mathbb{R}^{m\times n}\), shape [m, n]. A tensor is the same idea with any number of axes: shape [B, T, d] is a stack of \(B\) matrices, each \(T\times d\).

Notation used throughout the course: bold lowercase (\(\mathbf{x}\)) for vectors, uppercase (\(W\)) for matrices, \(x_i\) for the \(i\)-th entry of \(\mathbf{x}\), and \(W_{ij}\) for the entry in row \(i\), column \(j\). Indices start at 1 in math and at 0 in code. Shapes are written the way PyTorch prints tensor.shape.

Pitfall · Two meanings of "rank"

Some libraries call the number of axes a tensor's "rank" (a [B, T, d] tensor is "rank 3"). PyTorch calls it ndim. That's unrelated to the matrix rank in Section 01.10, which counts independent directions. When someone says "LoRA rank 16", they mean the second kind.

Rows or columns?

Math books treat vectors as columns and write \(\mathbf{y} = W\mathbf{x}\). Code stores a batch of vectors as the rows of a matrix \(X\) of shape [T, d] and computes \(Y = XW^{\top}\). Same numbers, same result, just transposed bookkeeping. This module uses the math convention for single vectors and the code convention for batches, and says which is which.

Vector arithmetic and geometry

There are two ways to look at a vector, and you'll want both. As a list of numbers, \(\mathbf{a} = (3, 1)\) is just data. As an arrow from the origin to the point (3, 1), it has a length and a direction. A 4096-dimensional embedding can't be drawn, but the algebra is identical, and most 2-D intuitions carry over.

Adding and scaling are done entry by entry:

$$\mathbf{a} + \mathbf{b} = (a_1 + b_1,\; a_2 + b_2,\; \ldots,\; a_d + b_d), \qquad c\,\mathbf{a} = (c\,a_1,\; c\,a_2,\; \ldots,\; c\,a_d)$$

Geometrically, \(\mathbf{a}+\mathbf{b}\) puts the tail of \(\mathbf{b}\) at the tip of \(\mathbf{a}\) (the diagonal of the parallelogram they span). Multiplying by a scalar \(c\) stretches the arrow by \(|c|\), and flips it if \(c\) is negative. Subtraction, \(\mathbf{b}-\mathbf{a}\), is the arrow that goes from \(\mathbf{a}\)'s tip to \(\mathbf{b}\)'s tip: the difference between two points.

Where addition shows up in an LLM

The transformer's residual stream (Module 06) is vector addition. Each layer reads the current token vector \(\mathbf{h}\), computes an update, and adds it back: \(\mathbf{h} \leftarrow \mathbf{h} + \text{attn}(\mathbf{h})\), then \(\mathbf{h} \leftarrow \mathbf{h} + \text{mlp}(\mathbf{h})\). Thirty-two layers means 64 additions to one running vector. Word2vec's famous \(\text{king} - \text{man} + \text{woman} \approx \text{queen}\) (Mikolov et al., 2013) is the same arithmetic on embeddings. That analogy holds loosely and only for some word pairs, but it's a good picture of "directions carry meaning".

Play with two vectors below. The readouts include the dot product, angle, projection and cosine, which the next two sections define properly. For now, watch what happens to the dot product when the arrows point the same way, at right angles, and in opposite directions.

The dot product

If you learn one operation in this module, learn this one. The dot product takes two vectors of the same length and returns one number. Attention scores, logits, cosine similarity, every entry of every matrix multiply: all of them are dot products.

$$\htmlClass{t1}{\mathbf{a}}\cdot\htmlClass{t2}{\mathbf{b}} = \sum_{\htmlClass{t3}{i}=1}^{\htmlClass{t4}{d}} \htmlClass{t1}{a_i}\,\htmlClass{t2}{b_i} = a_1b_1 + a_2b_2 + \cdots + a_db_d$$
\(\mathbf{a}, a_i\)
the first vector and its \(i\)-th entry
\(\mathbf{b}, b_i\)
the second vector, same length as \(\mathbf{a}\)
\(i\)
the position being multiplied; \(\sum\) means "add up over every \(i\)"
\(d\)
the dimension: 2 in the widget, 128 for an attention head, 4096 for a Llama-3-8B hidden vector

In wordsPair up the entries position by position, multiply each pair, and add the products. For \(\mathbf{a}=(1,2,3)\) and \(\mathbf{b}=(4,-5,6)\): \(4 - 10 + 18 = 12\).

Why it mattersIt costs \(d\) multiplies and \(d\) adds, \(2d\) FLOPs, and it's trivially parallel. That's the unit of work everything in Section 01.6 is counted in.

$$\mathbf{a}\cdot\mathbf{b} = \htmlClass{t1}{\lVert\mathbf{a}\rVert}\;\htmlClass{t2}{\lVert\mathbf{b}\rVert}\;\htmlClass{t3}{\cos\theta}$$
\(\lVert\mathbf{a}\rVert\)
length of \(\mathbf{a}\) (its L2 norm, next section)
\(\lVert\mathbf{b}\rVert\)
length of \(\mathbf{b}\)
\(\cos\theta\)
cosine of the angle between the arrows: +1 same direction, 0 at right angles, −1 opposite

In wordsThe dot product is "how long are they" times "how much do they point the same way". Positive means aligned, zero means unrelated (orthogonal), negative means opposed.

Why it mattersThis is why a dot product can serve as a match score. A query vector that points the same way as a key vector gets a big positive score. One at right angles gets zero. Attention is built on exactly that.

Think first: why do the two formulas give the same number?
Take the triangle formed by \(\mathbf{a}\), \(\mathbf{b}\), and \(\mathbf{a}-\mathbf{b}\). The law of cosines says \(\lVert\mathbf{a}-\mathbf{b}\rVert^2 = \lVert\mathbf{a}\rVert^2 + \lVert\mathbf{b}\rVert^2 - 2\lVert\mathbf{a}\rVert\lVert\mathbf{b}\rVert\cos\theta\). Now expand the left side entry by entry: \(\sum_i (a_i-b_i)^2 = \sum_i a_i^2 + \sum_i b_i^2 - 2\sum_i a_ib_i\). The squared-length terms match on both sides, so \(\sum_i a_ib_i = \lVert\mathbf{a}\rVert\lVert\mathbf{b}\rVert\cos\theta\). In 4096 dimensions you can't see the angle, so this identity is how "angle" gets defined there.

The projection of \(\mathbf{b}\) onto \(\mathbf{a}\) asks how far \(\mathbf{b}\) reaches along \(\mathbf{a}\)'s direction. Its signed length is \(\mathbf{a}\cdot\mathbf{b}/\lVert\mathbf{a}\rVert\). That's the gold segment in the widget above. Interpretability work uses this constantly: "how much of this hidden vector lies along the 'French' direction?" is a projection.

Two places an LLM computes dot products

Logits. The last step of every forward pass multiplies the final hidden vector \(\mathbf{h}\in\mathbb{R}^{4096}\) by the output embedding of each vocabulary entry. That's 128,256 dot products, one per possible next token, and the largest one is the model's top guess.

Attention scores. Each token emits a query \(\mathbf{q}\) ("what am I looking for?") and a key \(\mathbf{k}\) ("what do I contain?"). The score between two tokens is \(\mathbf{q}\cdot\mathbf{k}\), and a softmax (Module 03) turns a row of scores into weights that sum to 1. The widget below does this in two dimensions.

What the widget shows

Rotating the query changes which key wins. Lengthening it changes how decisively it wins: every score scales by \(\lVert\mathbf{q}\rVert\), and softmax of bigger numbers is spikier. Longer keys also get an edge, because a dot product rewards length as well as alignment. Real attention controls this with the \(1/\sqrt{d_k}\) factor in Section 01.7, and some models also normalize queries and keys ("QK-norm").

Norms, normalization, and cosine similarity

A norm measures how big a vector is. There's more than one sensible way to do that, and two of them matter in practice.

$$\htmlClass{t1}{\lVert\mathbf{x}\rVert_2} = \sqrt{\sum_{i=1}^{d} \htmlClass{t3}{x_i}^{2}} = \sqrt{\mathbf{x}\cdot\mathbf{x}}, \qquad \htmlClass{t2}{\lVert\mathbf{x}\rVert_1} = \sum_{i=1}^{d} \lvert \htmlClass{t3}{x_i} \rvert$$
\(\lVert\mathbf{x}\rVert_2\)
L2 (Euclidean) norm: the straight-line length of the arrow. Written \(\lVert\mathbf{x}\rVert\) when no subscript is given
\(\lVert\mathbf{x}\rVert_1\)
L1 (Manhattan) norm: total distance if you can only move along the axes
\(x_i\)
entries of the vector; \(\lvert\cdot\rvert\) is absolute value

In wordsFor \(\mathbf{x}=(3,-4)\): L2 is \(\sqrt{9+16}=5\), the hypotenuse. L1 is \(3+4=7\), walking the two legs. The L2 norm is also the square root of the vector's dot product with itself.

Why it mattersL2 is everywhere in training: gradient clipping caps the global L2 norm of all gradients (clip_grad_norm_, often at 1.0), and weight decay pulls weights toward a smaller L2 norm. L1 shows up where you want sparsity, because penalizing it pushes small entries to exactly zero. The sparse autoencoders used in interpretability research put an L1 penalty on their features for that reason.

Normalization

Dividing a vector by its own length gives a unit vector, which keeps the direction and throws away the size:

$$\hat{\mathbf{x}} = \frac{\mathbf{x}}{\lVert\mathbf{x}\rVert_2}, \qquad \lVert\hat{\mathbf{x}}\rVert_2 = 1, \qquad \text{RMSNorm}(\mathbf{x}) = \mathbf{g}\odot\frac{\mathbf{x}}{\sqrt{\tfrac{1}{d}\sum_{i} x_i^2 + \epsilon}}$$

The right-hand formula is RMSNorm (Zhang & Sennrich, 2019), which runs twice per layer in Llama-family models. The denominator is the root-mean-square of the entries, which equals \(\lVert\mathbf{x}\rVert_2/\sqrt{d}\), so RMSNorm rescales every token vector to length about \(\sqrt{d}\) (64 for \(d=4096\)) before multiplying entry-wise (\(\odot\)) by a learned gain \(\mathbf{g}\). \(\epsilon\) is a tiny constant like \(10^{-5}\) that prevents division by zero. Module 06 covers why the network needs this. For now, notice it's just "divide by the norm".

Cosine similarity

$$\htmlClass{t1}{\cos(\mathbf{a},\mathbf{b})} = \frac{\htmlClass{t2}{\mathbf{a}\cdot\mathbf{b}}}{\htmlClass{t3}{\lVert\mathbf{a}\rVert_2\,\lVert\mathbf{b}\rVert_2}} = \htmlClass{t4}{\hat{\mathbf{a}}\cdot\hat{\mathbf{b}}}$$
\(\cos(\mathbf{a},\mathbf{b})\)
a number from −1 to +1 that ignores length entirely
\(\mathbf{a}\cdot\mathbf{b}\)
the raw dot product
\(\lVert\mathbf{a}\rVert\lVert\mathbf{b}\rVert\)
the product of lengths, divided out
\(\hat{\mathbf{a}}\cdot\hat{\mathbf{b}}\)
equivalently: normalize both first, then take a plain dot product

In wordsRearrange the geometric dot product to solve for the cosine. For \((1,2,3)\) and \((4,-5,6)\): \(12 / (\sqrt{14}\cdot\sqrt{77}) = 12/32.83 = 0.365\), an angle of about 68.6°.

Why it mattersThis is how retrieval works (Module 11). Embed the question and every document chunk, then rank chunks by cosine with the question. Chunks that mean similar things get vectors pointing in similar directions, however long or short the text was.

MLE angle · Normalize once, then use the dot product

Vector indexes are fastest at raw inner products. So the standard trick is to L2-normalize every embedding when you store it (normalize_embeddings=True in sentence-transformers) and use an inner-product index such as FAISS IndexFlatIP. For unit vectors, \(\mathbf{a}\cdot\mathbf{b}\) is the cosine, and \(\lVert\mathbf{a}-\mathbf{b}\rVert^2 = 2 - 2\cos(\mathbf{a},\mathbf{b})\), so Euclidean distance ranks results in exactly the same order. Forget to normalize and long chunks quietly outrank relevant ones.

Think first: two random 4096-dimensional vectors. What's their cosine?
Almost exactly 0. If the entries are independent with mean zero, the dot product is a sum of 4096 terms that are as likely to be positive as negative, and most of it cancels. The cosine comes out roughly normal with standard deviation \(1/\sqrt{d} = 1/64 \approx 0.016\). In high dimensions, "unrelated" means "nearly orthogonal", and there's room for a very large number of nearly orthogonal directions. That's part of why a 4096-d hidden vector can hold many features at once. Trained embeddings aren't random, though: they often share a common direction, so unrelated texts can still score 0.2 to 0.5 against each other.
Caveat · Cosine scores aren't universal

A cosine of 0.8 means different things for different embedding models, and scores from two different models can't be compared at all. Pick retrieval thresholds by measuring on your own labelled queries, not by intuition about what "0.8" should mean.

Matrices as transformations

A matrix is a grid of numbers, but its job is to be a function: feed it a vector and it returns another vector. Take a 2×2 matrix \(A\) with first row \((a, b)\) and second row \((c, d)\), and think of it as two columns:

$$A = \big[\;\mathbf{a}_1 \;\;\; \mathbf{a}_2\;\big], \quad \mathbf{a}_1 = \begin{bmatrix} a \\ c \end{bmatrix},\; \mathbf{a}_2 = \begin{bmatrix} b \\ d \end{bmatrix}, \qquad A\mathbf{x} = x_1\begin{bmatrix} a \\ c \end{bmatrix} + x_2\begin{bmatrix} b \\ d \end{bmatrix} = \begin{bmatrix} a x_1 + b x_2 \\ c x_1 + d x_2 \end{bmatrix}$$

Read it two ways. Row view: each output entry is a dot product of one row of \(A\) with \(\mathbf{x}\). Column view: the output is a weighted mix of \(A\)'s columns, with \(\mathbf{x}\)'s entries as the weights. The column view gives you the key picture: column 1 is where the basis vector \(\mathbf{e}_1 = (1,0)\) lands, column 2 is where \(\mathbf{e}_2 = (0,1)\) lands, and every other vector follows along.

Definition · Linear

A function \(f\) is linear if \(f(\mathbf{x}+\mathbf{y}) = f(\mathbf{x}) + f(\mathbf{y})\) and \(f(c\,\mathbf{x}) = c\,f(\mathbf{x})\). Every matrix is a linear function and every linear function between finite-dimensional spaces is a matrix. Geometrically: the origin stays put, straight lines stay straight, and evenly spaced grid lines stay evenly spaced (though they may tilt, stretch, or collapse).

$$\det \htmlClass{t5}{A} = \htmlClass{t1}{a}\,\htmlClass{t4}{d} - \htmlClass{t2}{b}\,\htmlClass{t3}{c}$$
\(A\)
the matrix with rows \((a, b)\) and \((c, d)\)
\(a\)
top-left: how much \(x_1\) feeds output 1
\(d\)
bottom-right: how much \(x_2\) feeds output 2
\(b\)
top-right: how much \(x_2\) leaks into output 1
\(c\)
bottom-left: how much \(x_1\) leaks into output 2

In wordsThe determinant is the signed area of the parallelogram the unit square turns into. \(\det = 2\) doubles every area. A negative determinant means the plane got flipped over, like a mirror image. \(\det = 0\) means the square was squashed flat onto a line or a point.

Why it mattersA zero determinant means information was destroyed: two different inputs land on the same output, so there's no inverse matrix that can undo it. For bigger and non-square matrices the same idea is called rank (Section 01.10).

Weight matrices in an LLM are rarely square, and they transform between spaces of different sizes. Llama-3-8B's k_proj is \(1024\times4096\): it maps a 4096-dimensional hidden vector down to 1024 numbers (8 key heads of 128). It can't be undone, because you can't recover 4096 numbers from 1024. The MLP's up_proj goes the other way, 4096 up to 14,336.

Pitfall · Stacked linear layers collapse

Two matrices in a row are still one matrix: \(W_2(W_1\mathbf{x}) = (W_2W_1)\mathbf{x}\). A hundred linear layers with nothing in between can only do what a single matrix can do. The nonlinear activation between layers (SiLU, GELU, ReLU; Module 04) is what lets depth add expressive power. Where nonlinearity is absent, as in LoRA's \(B\) and \(A\), the product really is just one matrix, and that's exactly the property LoRA relies on to merge adapters back into the weights.

Matrix multiplication

Multiplying two matrices applies one transformation after the other. In practice it's the same thing as "apply \(A\) to many vectors at once": each column of \(B\) is a vector, and each column of the result is \(A\) applied to it. Every entry of the result is a single dot product.

$$\htmlClass{t1}{C_{ij}} = \sum_{\htmlClass{t4}{k}=1}^{\htmlClass{t5}{K}} \htmlClass{t2}{A_{ik}}\,\htmlClass{t3}{B_{kj}}$$
\(C_{ij}\)
the output entry in row \(i\), column \(j\)
\(A_{ik}\)
walk along row \(i\) of \(A\)
\(B_{kj}\)
walk down column \(j\) of \(B\)
\(k\)
the shared index, which advances along both at once
\(K\)
the inner dimension: columns of \(A\), which must equal rows of \(B\)

In wordsEntry \((i, j)\) of the product is the dot product of row \(i\) of \(A\) with column \(j\) of \(B\).

Why it mattersEvery one of the \(M\times N\) outputs is independent of the others, so thousands of GPU cores can compute them at the same time. That's the first half of why GPUs and matmuls get along (Section 01.11).

$$\underbrace{[\htmlClass{t1}{M},\, \htmlClass{t3}{K}]}_{A} \times \underbrace{[\htmlClass{t3}{K},\, \htmlClass{t2}{N}]}_{B} = \underbrace{[\htmlClass{t1}{M},\, \htmlClass{t2}{N}]}_{C}, \qquad \htmlClass{t4}{\text{FLOPs}} = 2\,\htmlClass{t1}{M}\,\htmlClass{t2}{N}\,\htmlClass{t3}{K}$$
\(M\)
rows of \(A\) and of the output. In a linear layer: the number of tokens
\(N\)
columns of \(B\) and of the output. In a linear layer: output features
\(K\)
the inner dimension that gets summed away. It has to match, or the product isn't defined
FLOPs
floating-point operations: \(MN\) outputs × \(K\) multiplies and \(K\) adds each

In wordsThe inner dimensions must match and then vanish, and the outer ones survive. The cost is two times the product of all three sizes. (The \(M, N, K\) names are the same ones cuBLAS and CUTLASS use for GEMM, "general matrix multiply".)

Why it mattersLlama-3-8B's q_proj on a 2048-token prompt: \([2048, 4096]\times[4096, 4096]\) costs \(2\cdot2048\cdot4096\cdot4096 \approx 68.7\) GFLOP. At an H100's 989 TFLOP/s dense bf16 peak, that's about 70 µs, if it ran at peak. Per token, a weight matrix with \(KN\) parameters costs \(2KN\) FLOPs: two FLOPs per parameter per token. That's where the "2" in Module 07's \(6ND\) training-cost rule comes from.

View 1 · dot products

Rows meet columns

\(C_{ij}\) is row \(i\) of \(A\) dotted with column \(j\) of \(B\). This is how you compute an entry by hand, and how attention scores are read off.

View 2 · column mixing

Outputs are blends

Column \(j\) of \(C\) is a mix of \(A\)'s columns, with weights from column \(j\) of \(B\). This is how a linear layer builds outputs from learned feature directions.

View 3 · outer products

A sum of rank-1 layers

\(C = \sum_k A_{:,k}\,B_{k,:}\): column \(k\) of \(A\) times row \(k\) of \(B\) gives a full \(M\times N\) matrix, and \(C\) is the sum of \(K\) of them. This view leads straight to SVD and LoRA.

Pitfall · Order matters, twice

Matrix multiplication is not commutative: \(AB \neq BA\) in general, and often only one of them is even defined. A \([3,4]\) matrix times a \([4,2]\) works; the reverse order is a shape error. It is associative, \((AB)C = A(BC)\), but the costs of the two groupings can be wildly different (next box).

Think first: \(A\) and \(B\) are 4096×4096 and \(\mathbf{x}\) is a vector. Should you compute \((AB)\mathbf{x}\) or \(A(B\mathbf{x})\)?
Same answer, very different bill. \((AB)\mathbf{x}\) first does a full matrix–matrix product: \(2\cdot4096^3 \approx 137\) GFLOP, plus a cheap matrix–vector product. \(A(B\mathbf{x})\) does two matrix–vector products: \(2\times2\cdot4096^2 \approx 67\) MFLOP. That's about 2000× less work. LoRA uses this: its update is computed as \(B(A\mathbf{x})\), never by forming the full \(BA\) matrix during training.
An embedding lookup is a matmul in disguise

Write token ID \(t\) as a one-hot vector \(\mathbf{o}\) (a 1 in position \(t\) and 0 in the other 128,255 positions). Then \(\mathbf{o}^{\top}E\) picks out row \(t\) of the embedding table \(E\). Libraries never do this multiply: indexing gives the same answer without 128,256 wasted multiply-adds per entry. But it's why the embedding table gets gradients like any other weight matrix, and why the input embedding and output unembedding can share one matrix ("tied embeddings", common in small models).

Transpose, and why attention uses QKᵀ

The transpose \(A^{\top}\) flips a matrix across its diagonal: rows become columns. If \(A\) is \([m, n]\), then \(A^{\top}\) is \([n, m]\), and \((A^{\top})_{ij} = A_{ji}\). Two facts you'll use constantly: \((A^{\top})^{\top} = A\), and \((AB)^{\top} = B^{\top}A^{\top}\) (the order reverses, so the shapes still line up). A dot product is itself a tiny matmul: \(\mathbf{a}\cdot\mathbf{b} = \mathbf{a}^{\top}\mathbf{b}\), a \([1,d]\) row times a \([d,1]\) column.

Now attention. Stack the query vectors of all \(T\) tokens as the rows of \(Q\), shape \([T, d_k]\), and the key vectors as the rows of \(K\), also \([T, d_k]\). You want the dot product of every query with every key. \(QK\) doesn't work, since \([T, d_k]\times[T, d_k]\) has mismatched inner dimensions. Transposing \(K\) turns its rows into columns, and the shape rule does the rest: \([T, d_k]\times[d_k, T] = [T, T]\).

$$\htmlClass{t1}{S} = \frac{\htmlClass{t2}{Q}\,\htmlClass{t3}{K}^{\top}}{\sqrt{\htmlClass{t4}{d_k}}}, \qquad \htmlClass{t1}{S_{ij}} = \frac{\htmlClass{t2}{\mathbf{q}_i}\cdot\htmlClass{t3}{\mathbf{k}_j}}{\sqrt{\htmlClass{t4}{d_k}}}$$
\(S\)
score matrix, \([T, T]\): row \(i\) holds token \(i\)'s score for every token \(j\)
\(Q, \mathbf{q}_i\)
queries, \([T, d_k]\); row \(i\) is token \(i\)'s query
\(K, \mathbf{k}_j\)
keys, \([T, d_k]\); the transpose makes row \(j\) into column \(j\)
\(d_k\)
head dimension (128 in Llama-3-8B). Dividing by \(\sqrt{d_k}\) keeps the scores' spread near 1

In wordsOne matrix multiply computes all \(T^2\) query–key dot products. Then each row goes through softmax and is used to average the value vectors (Module 06).

Why it mattersThe score matrix grows as \(T^2\). At \(T = 8192\), that's 67M scores per head; across 32 heads in bf16, about 4.3 GB per layer for one sequence. That's why FlashAttention (Dao et al., 2022) computes it in tiles and never stores the whole thing.

Think first: why divide by \(\sqrt{d_k}\) and not by \(d_k\)?
Suppose query and key entries are independent with mean 0 and variance 1. Each product \(q_ik_i\) then has variance 1, and the dot product sums \(d_k\) of them, so its variance is \(d_k\) and its standard deviation is \(\sqrt{d_k}\). For \(d_k=128\), raw scores spread over roughly ±11, and softmax of numbers that far apart is nearly one-hot: one token gets all the attention and gradients for the rest vanish. Dividing by \(\sqrt{d_k} \approx 11.3\) brings the spread back to about 1. Dividing by \(d_k\) would overshoot and make attention nearly uniform. Vaswani et al. (2017) give exactly this argument.
MLE angle · Transposes are usually free

In PyTorch, k.transpose(-2, -1) doesn't move any data. It returns a view with swapped strides, and matmul kernels accept transposed operands directly. Use .mT or transpose(-2, -1) on batched tensors; .T on a tensor with more than two dimensions is deprecated. A .contiguous() after a transpose does copy, so in hot paths check whether you really need it.

Batched matmuls and broadcasting

Real tensors have more than two axes. Hidden states are \([B, T, d]\); attention works on \([B, H, T, d_k]\). The rule for @ (torch.matmul) is simple: the last two axes are multiplied as matrices, and every axis before them is a batch axis, so the same matmul runs independently for each batch index.

$$[\ldots,\, M,\, K] \times [\ldots,\, K,\, N] \;\to\; [\ldots,\, M,\, N], \qquad [B, T, d] \times [d, d_{\text{ff}}] \;\to\; [B, T, d_{\text{ff}}]$$

In the second example the weight matrix has no batch axes at all. It gets broadcast: the one matrix is reused for all \(B\times T\) token vectors. Under the hood, PyTorch reshapes \([B, T, d]\) to \([B\cdot T, d]\), runs a single big GEMM, and reshapes back. The cost is \(2\cdot BT\cdot d\cdot d_{\text{ff}}\) FLOPs, which is just \(2MNK\) with \(M = BT\).

The broadcasting rules

When two tensors of different shapes meet in an elementwise operation (+, *, masked_fill), NumPy and PyTorch line their shapes up from the right and compare axis by axis:

  1. If one tensor has fewer axes, pretend it has extra size-1 axes on the left.
  2. Two sizes are compatible if they're equal, or if one of them is 1. A size-1 axis is stretched (without copying) to match.
  3. Anything else is an error.

So a bias [d_ff] plus activations [B, T, d_ff] works, and a causal mask [T, T] applies to scores [B, H, T, T] for every batch element and head at once.

Pitfall · The silent [N, N]

Predictions of shape [N, 1] minus targets of shape [N] doesn't fail. Rule 1 turns the targets into [1, N], rule 2 stretches both, and you get an [N, N] matrix of every prediction minus every target. Take its mean and you have a loss that trains, slowly and wrongly. When a loss curve looks oddly flat, print the shapes before anything else.

The linear layer and parameter counting

Put a matrix multiply and a bias together and you have the most common building block in deep learning. Almost every parameter in an LLM lives in one of these.

$$\htmlClass{t1}{\mathbf{y}} = \htmlClass{t2}{W}\,\htmlClass{t3}{\mathbf{x}} + \htmlClass{t4}{\mathbf{b}}, \qquad \htmlClass{t5}{P} = \htmlClass{t6}{d_{\text{out}}}\cdot\htmlClass{t7}{d_{\text{in}}} + \htmlClass{t6}{d_{\text{out}}}$$
\(\mathbf{y}\)
output vector, \([d_{\text{out}}]\)
\(W\)
weight matrix, \([d_{\text{out}}, d_{\text{in}}]\). This is exactly how PyTorch stores nn.Linear.weight
\(\mathbf{x}\)
input vector, \([d_{\text{in}}]\)
\(\mathbf{b}\)
bias, \([d_{\text{out}}]\). Llama-family models drop it (bias=False)
\(P\)
parameter count of the layer
\(d_{\text{out}}\)
output features
\(d_{\text{in}}\)
input features

In wordsEach output is a dot product of one row of \(W\) with the input, plus an offset. One row per output, one column per input.

Why it mattersFor a batch stored as rows, PyTorch computes x @ W.T + b. That's why nn.Linear(4096, 1024).weight.shape is [1024, 4096], "backwards" from the constructor arguments, and why so many shape bugs are really transpose bugs.

MLE angle · FLOPs per token from a parameter count

Since a matrix with \(P\) entries costs \(2P\) FLOPs per token, a forward pass costs about 2 FLOPs per matmul parameter per token. The input embedding is a lookup, so it's excluded: Llama-3-8B has about 7.5B matmul parameters, so roughly 15 GFLOP per token, plus attention-score work that grows with context length. Training adds the backward pass at about twice the forward cost, which gives Module 07's \(6ND\).

Rank, low-rank factorization, and SVD

The rank of a matrix is the number of genuinely independent directions in its output, equivalently the number of linearly independent columns (which always equals the number of independent rows). A \([4096, 4096]\) matrix has rank at most 4096, but it can be much lower. The 2×2 "squash" preset in the transformation widget has rank 1: everything lands on one line.

The simplest low-rank matrix is an outer product \(\mathbf{u}\mathbf{v}^{\top}\): a \([m,1]\) column times a \([1,n]\) row, giving an \([m,n]\) matrix whose every row is a multiple of \(\mathbf{v}^{\top}\). It has rank 1, and storing it takes \(m+n\) numbers instead of \(mn\). View 3 of matrix multiplication says any product of an \([m,r]\) and an \([r,n]\) matrix is a sum of \(r\) such outer products, so it has rank at most \(r\). The singular value decomposition says every matrix can be written that way, in the best possible order.

$$\htmlClass{t1}{A} = \htmlClass{t2}{U}\,\htmlClass{t3}{\Sigma}\,\htmlClass{t4}{V}^{\top} = \sum_{i=1}^{\htmlClass{t5}{r}} \htmlClass{t3}{\sigma_i}\,\htmlClass{t2}{\mathbf{u}_i}\,\htmlClass{t4}{\mathbf{v}_i}^{\top}$$
\(A\)
any \([m, n]\) matrix: a weight, a weight update, an image
\(U, \mathbf{u}_i\)
\([m, r]\); orthonormal columns (unit length, mutually perpendicular): the output directions
\(\Sigma, \sigma_i\)
diagonal \([r, r]\) of singular values \(\sigma_1 \ge \sigma_2 \ge \cdots \ge 0\): how much \(A\) stretches along each direction
\(V, \mathbf{v}_i\)
\([n, r]\); orthonormal columns: the input directions
\(r\)
the rank: how many \(\sigma_i\) are non-zero

In wordsEvery matrix is a rotation, then a stretch along perpendicular axes, then another rotation. Equivalently, it's a sum of rank-1 layers, sorted from most to least important.

Why it mattersThe singular values are an importance ranking. If they drop off fast, the matrix is "approximately low rank", and a few terms reproduce almost all of it.

$$\htmlClass{t1}{A_k} = \sum_{i=1}^{\htmlClass{t2}{k}} \sigma_i\,\mathbf{u}_i\mathbf{v}_i^{\top}, \qquad \htmlClass{t3}{\lVert A - A_k \rVert_F^{2}} = \sum_{i \gt \htmlClass{t2}{k}} \htmlClass{t4}{\sigma_i^{2}}$$
\(A_k\)
keep only the first \(k\) terms: a rank-\(k\) matrix, storable as \(k(m+n)\) numbers
\(k\)
how many terms you keep
\(\lVert\cdot\rVert_F^2\)
squared Frobenius norm: the sum of every squared entry, i.e. L2 for matrices
\(\sigma_i^2\)
the "energy" in each dropped term

In wordsTruncating the SVD gives the closest rank-\(k\) matrix there is (Eckart & Young, 1936), and the squared error is exactly the squared singular values you threw away.

Setting up LoRA

Fine-tuning changes a pretrained weight \(W_0\) to \(W_0 + \Delta W\). Hu et al. (2021) bet that \(\Delta W\) is approximately low rank, as with the "low-rank plus noise" pattern above, so they never form it at full size. They train two thin matrices whose product is a rank-\(r\) update.

$$\htmlClass{t1}{W} = \htmlClass{t2}{W_0} + \htmlClass{t3}{B}\,\htmlClass{t4}{A}, \qquad \htmlClass{t3}{B}\in\mathbb{R}^{\htmlClass{t5}{d}\times\htmlClass{t6}{r}},\;\; \htmlClass{t4}{A}\in\mathbb{R}^{\htmlClass{t6}{r}\times\htmlClass{t7}{k}}, \qquad \text{params} = \htmlClass{t6}{r}\,(\htmlClass{t5}{d}+\htmlClass{t7}{k}) \;\text{ vs }\; \htmlClass{t5}{d}\,\htmlClass{t7}{k}$$
\(W\)
the adapted weight, still \([d, k]\)
\(W_0\)
pretrained weight, frozen
\(B\)
\([d, r]\), trained; initialized to zero so training starts exactly at \(W_0\)
\(A\)
\([r, k]\), trained; random init (a different \(A\) from the SVD's matrix above)
\(d\)
output dimension of the weight
\(r\)
LoRA rank, typically 8 to 64
\(k\)
input dimension of the weight

In wordsReplace one big \(d\times k\) update with a tall-thin times a short-wide pair. The product can only express \(r\) directions, and in exchange it costs the sum of the dimensions instead of their product.

Why it mattersA 4096×4096 q_proj at \(r = 16\): \(16\times(4096+4096) = 131{,}072\) trainable parameters instead of 16,777,216, which is 0.78%. Module 10 builds the full training setup on this.

Caveat · Pretrained weights aren't low rank

The bet is about the update \(\Delta W\), not \(W_0\). Pretrained weight matrices usually have slowly decaying spectra, closer to the "random noise" pattern, so truncating their SVD to save memory costs real quality. Some LoRA variants do borrow the SVD: PiSSA (Meng et al., 2024) initializes \(B\) and \(A\) from the top singular directions of \(W_0\). Standard LoRA starts from \(BA = 0\).

Why GPUs love matmuls

A GPU has two speed limits: how many FLOPs per second its arithmetic units can do, and how many bytes per second it can stream from memory. An H100 SXM does about 989 TFLOP/s of dense bf16 matmul against 3.35 TB/s of memory bandwidth. To keep the arithmetic busy, a kernel must do roughly 295 FLOPs for every byte it reads. Module 08 builds the full roofline model; here's the matmul half of the story.

$$\htmlClass{t1}{\text{AI}} = \frac{2\,M\,N\,K}{\htmlClass{t2}{b}\,(\htmlClass{t3}{MK} + \htmlClass{t4}{KN} + \htmlClass{t5}{MN})} \;\;\xrightarrow{\;M=N=K=n,\; b=2\;}\;\; \frac{n}{3}$$
AI
arithmetic intensity: FLOPs done per byte moved to or from memory
\(b\)
bytes per number: 2 for bf16, 4 for fp32
\(MK\)
entries of \(A\), read once
\(KN\)
entries of \(B\), read once
\(MN\)
entries of \(C\), written once

In wordsWork grows with the product of three sizes, while data grows with products of only two. Make the matrices bigger and each loaded number gets reused more times. A 4096³ bf16 matmul does about 1365 FLOPs per byte, far past the ridge. A matrix–vector product (\(M=1\)) reuses nothing and sits near 1 FLOP per byte.

Why it mattersThis is the whole prefill-versus-decode story of Module 08. Prefill pushes thousands of tokens through each weight matrix (\(M\) large, compute-bound). Decode pushes one token per sequence (\(M\) = batch size, memory-bound). Same weights, same math, a factor of a thousand in efficiency.

GPUs also have dedicated matmul hardware. NVIDIA's tensor cores multiply small tiles (for example 16×16 blocks) in one instruction. On an H100 they deliver roughly fifteen times the throughput of the ordinary fp32 units. A well-written GEMM loads a tile of \(A\) and a tile of \(B\) into fast on-chip memory, multiplies them there, and accumulates, so each number fetched from slow memory gets reused across a whole tile. That tiling is exactly the reuse the arithmetic intensity formula counts.

MLE angle · Shapes that are friendly to hardware

Tensor-core kernels work in tiles, so dimensions that are multiples of 64 or 128 avoid wasted partial tiles. That's why model widths are numbers like 4096 and 14,336 (= 112 × 128), and why Karpathy's nanoGPT pads GPT-2's 50,257-token vocabulary to 50,304 (a multiple of 64) and reports a noticeable speedup from that one change. If a custom layer runs oddly slow, check whether one of its dimensions is something like 1000 or 50,257.

3. Attention scores three ways: matmul, einsum, fused kernel

einsum names every axis with a letter. Letters that appear in the inputs but not in the output are summed over. Here d disappears, so it's a dot product over the head dimension for every \((b, h, i, j)\).


import math
import torch
import torch.nn.functional as F

B, H, T, d_k = 2, 32, 16, 128
q, k, v = (torch.randn(B, H, T, d_k) for _ in range(3))

s1 = q @ k.transpose(-2, -1) / math.sqrt(d_k)                 # [B, H, T, T]
s2 = torch.einsum("bhid,bhjd->bhij", q, k) / math.sqrt(d_k)   # same thing, axes named
print(s1.shape, torch.allclose(s1, s2, atol=1e-4))             # torch.Size([2, 32, 16, 16]) True

print((q @ k.transpose(-2, -1)).std().item(), s1.std().item())  # about 11.3 vs about 1.0

mask = torch.ones(T, T, dtype=torch.bool).tril()               # [T, T] broadcasts over B and H
attn = torch.softmax(s1.masked_fill(~mask, float("-inf")), dim=-1)
out = attn @ v                                                 # [B, H, T, d_k]

ref = F.scaled_dot_product_attention(q, k, v, is_causal=True)
print(torch.allclose(out, ref, atol=1e-4))                     # True

4. SVD, rank-k error, and LoRA-shaped factors


import torch

torch.manual_seed(0)
d, k, r_true = 1024, 1024, 8
# "rank 8 plus a little noise": the shape of matrix LoRA bets a fine-tuning update has
delta = torch.randn(d, r_true) @ torch.randn(r_true, k) + 0.05 * torch.randn(d, k)

U, S, Vh = torch.linalg.svd(delta, full_matrices=False)   # delta = U @ diag(S) @ Vh
print(S[:10])                   # eight large values, then a cliff

def rank_k(r):
    return U[:, :r] @ torch.diag(S[:r]) @ Vh[:r, :]

total = torch.linalg.norm(delta)
for r in (1, 4, 8, 16, 64):
    err = (torch.linalg.norm(delta - rank_k(r)) / total).item()
    tail = ((S[r:] ** 2).sum().sqrt() / total).item()     # Eckart-Young prediction
    print(f"rank {r:3d}: rel. error {err:.4f}  (from dropped sigmas {tail:.4f})  "
          f"params {r * (d + k):,} vs {d * k:,}")

# LoRA-shaped factors from the SVD: B is [d, r], A is [r, k], and B @ A is the rank-r approximation
r = 8
B_ = U[:, :r] * S[:r].sqrt()
A_ = S[:r].sqrt()[:, None] * Vh[:r]
print(B_.shape, A_.shape, torch.allclose(B_ @ A_, rank_k(r), atol=1e-3))

5. Measure arithmetic intensity on your own hardware


import time
import torch

dev = "cuda" if torch.cuda.is_available() else "mps" if torch.backends.mps.is_available() else "cpu"
dt = torch.float32 if dev == "cpu" else torch.float16

def sync():
    if dev == "cuda":
        torch.cuda.synchronize()
    elif dev == "mps":
        torch.mps.synchronize()

def bench(M, K, N, iters=20):
    A = torch.randn(M, K, device=dev, dtype=dt)
    B = torch.randn(K, N, device=dev, dtype=dt)
    for _ in range(3):
        A @ B                                   # warm-up
    sync()
    t0 = time.perf_counter()
    for _ in range(iters):
        A @ B
    sync()
    sec = (time.perf_counter() - t0) / iters
    flops = 2 * M * N * K
    nbytes = A.element_size() * (M * K + K * N + M * N)
    print(f"T={M:5d}  {flops / sec / 1e12:7.2f} TFLOP/s  {nbytes / sec / 1e9:7.1f} GB/s  AI={flops / nbytes:7.1f}")

for T in (1, 8, 64, 512, 4096):
    bench(T, 4096, 4096)                        # one Llama-sized projection, T tokens at a time

You add LoRA with rank \(r = 8\) to a \([1024, 4096]\) weight (\(d = 1024\), \(k = 4096\)). How many trainable parameters does it add?

  1. 40,960
  2. 32,768
  3. 4,194,304
  4. 65,536
\(B\) is \([1024, 8]\) = 8,192 and \(A\) is \([8, 4096]\) = 32,768, so \(r(d+k) = 8\times5120 = 40{,}960\). That's about 1% of the 4,194,304 entries in the full matrix. 32,768 counts only \(A\).

Two non-zero embedding vectors have lengths 3 and 5 and a dot product of 0. What's their cosine similarity, and what happens to it if you double the first vector?

  1. 15, and it doubles to 30
  2. 0, and it stays 0
  3. 1, since cosine only measures direction
  4. Undefined, because the dot product is zero
\(\cos = 0/(3\times5) = 0\): the vectors are orthogonal. Scaling either vector multiplies both the numerator and the denominator by the same factor, so cosine never changes under scaling. That's the point of using it for retrieval.

What does the matrix with rows \((2, 1)\) and \((4, 2)\) do to the plane?

  1. Doubles every area
  2. Scales areas by 4 and flips orientation
  3. Squashes the whole plane onto a line: det 0, rank 1, no inverse
  4. Rotates by 45°
\(\det = 2\cdot2 - 1\cdot4 = 0\). The second column \((1, 2)\) is half the first column \((2, 4)\), so both basis vectors land on the same line, and so does every other vector. Distinct inputs collide, so it can't be undone.

In bf16, what's the approximate arithmetic intensity of \([1, 4096]\times[4096, 4096]\) (one decode token) versus \([4096, 4096]\times[4096, 4096]\) (a long prefill)?

  1. ≈ 1 vs ≈ 1365 FLOPs/byte
  2. ≈ 1365 vs ≈ 1 FLOPs/byte
  3. Both ≈ 4096 FLOPs/byte
  4. Both ≈ 2 FLOPs/byte: same weights, same intensity
One token: \(2\cdot4096^2\) FLOPs over about \(2\cdot4096^2\) bytes of weights, so ≈ 1. Square: \(2n^3/(2\cdot3n^2) = n/3 \approx 1365\). Same weight matrix, but in the prefill case every weight byte is reused across 4096 tokens. On an H100 (ridge ≈ 295) the first is memory-bound and the second compute-bound.
