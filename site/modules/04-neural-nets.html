Module 04 · How models work

Neural networks, and how they learn

Strip away the attention plumbing and a transformer is matrix multiplies with a cheap nonlinearity between them. It learns through one algorithm, backpropagation, which finds the gradient for every one of its billions of weights for about twice the cost of running it forward. This module builds both from a single neuron, and ends with a network you train inside this page.

~3 hoursprereqs: 01, 02, 03hands-on: micrograd, PyTorch

By the end you can

  2. Choose between ReLU, GELU, SiLU, sigmoid and tanh, and say what each derivative does to the gradient.
  3. Run backpropagation by hand on a computational graph, then write the same thing in matrix form for a whole layer.
  4. Explain why deep plain networks lose their gradients, and how initialization, normalization and residual connections fix that.

The artificial neuron

A neuron takes a list of numbers, multiplies each by a weight, adds them up with a bias, and passes the total through a fixed function. That's all. The weights say how much each input counts and in which direction. The bias shifts the threshold. The function, called the activation, bends the result so that stacking neurons gives you something more than a bigger linear formula.

$$\htmlClass{t1}{y} = \htmlClass{t2}{\varphi}\big(\htmlClass{t3}{\mathbf{w}}\cdot\htmlClass{t4}{\mathbf{x}} + \htmlClass{t5}{b}\big) = \htmlClass{t2}{\varphi}\Big(\sum_{i=1}^{n} \htmlClass{t3}{w_i}\,\htmlClass{t4}{x_i} + \htmlClass{t5}{b}\Big)$$
\(y\)
the neuron's output, a single number
\(\varphi\)
activation function, applied to one number (ReLU, GELU, tanh…)
\(\mathbf{w}\)
weights, one per input. Learned
\(\mathbf{x}\)
inputs: pixels, features, or the outputs of the previous layer
\(b\)
bias: a learned offset that moves the firing threshold

In wordsTake a dot product of the input with the weight vector, add a constant, squash. The dot product is large when the input points in the same direction as \(\mathbf{w}\) (Module 01), so a neuron is a detector for one direction in input space.

Why it mattersThe set of inputs where \(\mathbf{w}\cdot\mathbf{x} + b = 0\) is a hyperplane. A single neuron can only split space with one flat cut. With \(\varphi = \sigma\) it is exactly logistic regression.

Work the figure by hand once: \(0.8\cdot1.0 + (-0.3)(-2.0) + 1.2\cdot0.5 = 2.0\), plus the bias \(-0.5\) gives \(z = 1.5\), and ReLU leaves it at \(1.5\). If the bias were \(-2.5\), \(z\) would be \(-0.5\) and ReLU would output \(0\): the neuron stays silent for this input.

Think first: can one neuron learn XOR?
No. XOR labels the points (0,0) and (1,1) as one class and (0,1), (1,0) as the other. No single straight line separates those two pairs, and with any monotonic activation (step, sigmoid, tanh, ReLU) a single neuron's decision boundary is a straight line, because \(\varphi\) only rescales the signed distance from that line. Minsky and Papert made this point in 1969, and it stalled the field for years. Two hidden neurons solve it. You can watch a small network do so in the training widget at the end of this module (pick the XOR dataset).

Activation functions

Why have \(\varphi\) at all? Because without it, depth buys nothing. Two linear layers compose into one: \(W_2(W_1\mathbf{x}) = (W_2W_1)\mathbf{x}\). A hundred stacked linear layers are still one matrix. The activation is what lets each layer bend the space before the next layer cuts it.

Which bend? Early networks used smooth S-curves. Modern ones mostly use functions that look like "zero on the left, identity on the right", because those pass gradients through without shrinking them.

$$\htmlClass{t1}{\text{ReLU}}(x)=\max(0,x) \qquad \htmlClass{t2}{\text{GELU}}(x) = x\,\htmlClass{t4}{\Phi}(x) \qquad \htmlClass{t3}{\text{SiLU}}(x) = x\,\htmlClass{t5}{\sigma}(x)$$
ReLU
rectified linear unit. Derivative is exactly 1 for \(x \gt 0\), 0 for \(x \lt 0\). Popularized by AlexNet (Krizhevsky et al., 2012)
GELU
Gaussian error linear unit (Hendrycks & Gimpel, 2016). Used in BERT and GPT-2
SiLU
sigmoid linear unit, also called Swish (Ramachandran et al., 2017). The gate inside Llama's SwiGLU MLP (Module 06)
\(\Phi\)
standard normal CDF: the probability that a \(\mathcal{N}(0,1)\) draw is below \(x\)
\(\sigma\)
logistic sigmoid \(1/(1+e^{-x})\)

In wordsAll three behave like the identity for large positive inputs and like zero for large negative ones. They differ only near zero: ReLU has a hard corner, while GELU and SiLU round it off and dip slightly below zero (SiLU's minimum is about \(-0.28\), GELU's about \(-0.17\)).

Why it mattersA derivative of exactly 1 on the active side means gradients pass through a ReLU layer without shrinking. The smooth versions train slightly better in large models and are now the default. GPT-2 actually computes GELU with a tanh approximation, \(0.5x\,(1+\tanh(\sqrt{2/\pi}\,(x+0.044715x^3)))\), which you will still see in configs as gelu_new or gelu_pytorch_tanh.

$$\htmlClass{t1}{\sigma}(x) = \frac{1}{1+e^{-x}}, \quad \htmlClass{t2}{\sigma'}(x) = \sigma(x)\big(1-\sigma(x)\big) \le \tfrac14 \qquad\quad \htmlClass{t3}{\tanh}(x) = 2\sigma(2x)-1, \quad \htmlClass{t4}{\tanh'}(x) = 1-\tanh^2(x) \le 1$$
\(\sigma\)
sigmoid: squashes any number into (0, 1). Reads as a probability
\(\sigma'\)
its derivative, which peaks at only 0.25 (at \(x = 0\))
\(\tanh\)
hyperbolic tangent: a sigmoid stretched to (−1, 1), centred on zero
\(\tanh'\)
its derivative, peaking at 1, falling to ~0 once \(|x| \gt 3\)

In wordsBoth are S-curves that flatten out ("saturate") at the ends. Where the curve is flat, the derivative is near zero, and so is any gradient that has to pass through.

Why it mattersA sigmoid layer multiplies the backward signal by at most 0.25. Ten of them shrink it by at least \(4^{10} \approx 10^6\). That's why hidden layers moved to ReLU. Sigmoid survives where you want a value in (0, 1): output probabilities, and gates such as those in LSTMs.

Pitfall · dead ReLUs

If a ReLU unit's pre-activation is negative for every input in the data, its output and its gradient are both zero everywhere, so gradient descent can never revive it. A large learning-rate step that pushes the bias far negative is the usual cause. Symptom: a growing fraction of hidden units that output exactly 0 on every batch. Leaky ReLU, GELU and SiLU all have a nonzero slope on the left, which is one reason they replaced plain ReLU.

Multi-layer perceptrons

Put many neurons side by side and they form a layer. Each neuron has its own weight vector, so stacking those vectors as rows gives a weight matrix, and the whole layer becomes one matrix-vector product followed by an elementwise activation. Stack layers and you have a multi-layer perceptron (MLP), also called a feed-forward network.

$$\htmlClass{t1}{\mathbf{h}^{l}} = \htmlClass{t2}{\varphi}\big(\htmlClass{t3}{W^{l}}\,\htmlClass{t1}{\mathbf{h}^{l-1}} + \htmlClass{t4}{\mathbf{b}^{l}}\big), \qquad \htmlClass{t1}{\mathbf{h}^{0}} = \htmlClass{t5}{\mathbf{x}}, \qquad \hat{\mathbf{y}} = \htmlClass{t3}{W^{L}}\htmlClass{t1}{\mathbf{h}^{L-1}} + \htmlClass{t4}{\mathbf{b}^{L}}$$
\(\mathbf{h}^{l}\)
hidden activations after layer \(l\), a vector of length \(d_l\)
\(\varphi\)
activation, applied to each entry separately
\(W^{l}\)
weight matrix of shape \(d_l \times d_{l-1}\): row \(j\) is neuron \(j\)'s weight vector
\(\mathbf{b}^{l}\)
bias vector, length \(d_l\)
\(\mathbf{x}\)
the input, length \(d_0\)

In wordsEach layer computes a whole row of neurons at once with one matmul, bends every entry, and hands the result to the next layer. The last layer usually skips \(\varphi\) so it can output any real number (a logit or a regression value).

Why it mattersWith a batch, the input becomes a matrix \(X\) of shape \([B, d_{l-1}]\) and the layer is \(\varphi(XW^{\top} + \mathbf{b})\). That is exactly what PyTorch's nn.Linear computes, which is why its weight has shape [out_features, in_features].

Shapes are where most bugs live, so read them off the figure once: \(W^1\) maps 3 numbers to 4, so it is \(4\times3\). \(W^2\) is \(4\times4\). \(W^3\) is \(2\times4\). The input dimension is always the second index, because the matrix multiplies a column vector from the left.

Think first: how many parameters are in nn.Linear(4096, 14336)?
\(4096 \times 14336 = 58{,}720{,}256\) weights plus \(14{,}336\) biases \(= 58{,}734{,}592\). Llama-family models build these layers with bias=False, so in Llama it's exactly \(58{,}720{,}256\), about 117 MB in bf16. One layer's three MLP matrices are three times that.

What MLPs can represent

A network with one hidden layer of enough units can approximate any continuous function on a bounded region as closely as you like. This is the universal approximation theorem (Cybenko, 1989 for sigmoids; Hornik, 1991 more generally; Leshno et al., 1993 showed any non-polynomial activation works). For ReLU you can see why with a pencil: each unit contributes one bend.

$$\htmlClass{t1}{\hat f}(x) = \htmlClass{t2}{c_0} + \sum_{i=1}^{\htmlClass{t5}{N}} \htmlClass{t3}{c_i}\,\mathrm{ReLU}(x - \htmlClass{t4}{k_i})$$
\(\hat f\)
the network's output: a 1 → N → 1 ReLU MLP
\(c_0\)
output bias
\(c_i\)
output weight of hidden unit \(i\): how much the slope changes at its kink
\(k_i\)
kink location of unit \(i\), set by its input weight and bias (\(k_i = -b_i/w_i\))
\(N\)
number of hidden units

In wordsEach ReLU is flat until its kink, then rises in a straight line. Add up N of them with different weights and you get a curve made of straight segments with up to N bends. With enough bends you can trace any continuous curve.

Why it mattersIt turns "neural networks are universal" from a mystery into bookkeeping. For a smooth target, piecewise-linear interpolation error falls roughly as \(1/N^2\). For a jump it falls much more slowly, because no straight segment can be vertical.

What the theorem does not promise

It says a good set of weights exists. It says nothing about whether gradient descent will find them, how many units you need (it can be exponential in the input dimension), or whether the function will generalize beyond the training points. Depth matters in practice because some functions need exponentially fewer units when built from several layers than from one (Telgarsky, 2016). The theorem is an existence proof, not a recipe.

Loss functions

To learn, the network needs one number that says how wrong it is. That number is the loss, and everything in training is about pushing it down. Two losses cover most of what you'll see.

$$\htmlClass{t1}{\mathcal{L}}_{\text{MSE}} = \frac{1}{\htmlClass{t4}{n}}\sum_{i=1}^{\htmlClass{t4}{n}} \big(\htmlClass{t2}{\hat y_i} - \htmlClass{t3}{y_i}\big)^2, \qquad \frac{\partial \htmlClass{t1}{\mathcal{L}}}{\partial \htmlClass{t2}{\hat y_i}} = \frac{2}{\htmlClass{t4}{n}}\big(\htmlClass{t2}{\hat y_i} - \htmlClass{t3}{y_i}\big)$$
\(\mathcal{L}\)
the loss, one number for the whole batch
\(\hat y_i\)
the network's prediction for example \(i\)
\(y_i\)
the target value
\(n\)
batch size

In wordsAverage the squared misses. Big misses count disproportionately: an error of 3 costs nine times an error of 1. The gradient is simply "how far off, times two".

$$\htmlClass{t1}{\mathcal{L}}_{\text{CE}} = -\log \htmlClass{t2}{p_{y}}, \qquad \htmlClass{t2}{p_k} = \frac{e^{\htmlClass{t3}{z_k}}}{\sum_j e^{\htmlClass{t3}{z_j}}}, \qquad \frac{\partial \htmlClass{t1}{\mathcal{L}}}{\partial \htmlClass{t3}{z_k}} = \htmlClass{t2}{p_k} - \htmlClass{t4}{\mathbb{1}[k=y]}$$
\(\mathcal{L}\)
negative log-probability of the right answer, in nats (Module 03)
\(p_k\)
softmax probability of class \(k\); \(p_y\) is the one for the true class
\(z_k\)
logits: the raw, unnormalized scores from the last layer
\(\mathbb{1}[k=y]\)
1 for the true class, 0 for all others (the one-hot target)

In wordsTurn logits into probabilities and charge the model the surprise of the right answer. The gradient on the logits is "predicted probability minus truth": push the true class up by \(1-p_y\), push every other class down by its own probability.

Why it mattersThis is exactly the LLM pretraining loss, averaged over every token position, with a vocabulary of 100K+ classes. Giving the right token probability 0.01 costs \(\ln 100 \approx 4.6\) nats. The gradient never exceeds 1 in size, so it doesn't saturate the way MSE on a sigmoid output does.

Pitfall · softmax then log

Computing torch.log(torch.softmax(z, -1)) underflows: a probability of \(10^{-50}\) rounds to 0 in fp32 and its log is \(-\infty\). Pass raw logits to F.cross_entropy (or binary_cross_entropy_with_logits for two classes), which uses the log-sum-exp trick internally. Never apply softmax yourself before those functions; they already do it.

Backpropagation

Training needs \(\partial\mathcal{L}/\partial w\) for every weight \(w\). Computing them one at a time (nudge one weight, rerun the network) would cost one forward pass per parameter: \(8\times10^9\) passes for an 8B model, per step. Backpropagation gets all of them in one backward sweep. It is the chain rule from Module 02, applied in a particular order: start at the loss and work backwards, reusing each intermediate result once. Reverse-mode differentiation is older than deep learning; Rumelhart, Hinton & Williams (1986) made it the standard way to train neural networks.

Definition · computational graph

Write the computation as a graph: leaves are inputs and parameters, interior nodes are simple operations (\(+\), \(\times\), tanh, matmul…), and the root is the loss. Each node stores its forward value and, after the backward pass, its grad: \(\partial\mathcal{L}/\partial(\text{node})\). Every operation only needs to know its own local derivative.

On a graph, by hand

Here is one neuron with a squared-error loss, \(\mathcal{L} = (\tanh(wx+b) - y)^2\), broken into its primitive steps. Forward values flow left to right. Then the loss's grad is set to 1, and each node passes grad to its inputs, multiplied by its local derivative.

Three local rules cover almost everything:

  • Add copies the incoming grad to both inputs unchanged (its derivative is 1 in each direction).
  • Multiply sends each input the grad times the other input. For \(u = wx\), \(\partial u/\partial w = x\).
  • Fan-out: if a value feeds several nodes, its grad is the sum of what comes back along each path. That is why autograd code writes grad +=, never grad =.
Think first: for \(L = a\cdot b + a\), what is \(\partial L/\partial a\)?
\(b + 1\). The value \(a\) reaches \(L\) along two paths: through the multiply (contributing \(b\)) and directly through the add (contributing 1). Pick the "fan-out" preset in the widget above and watch \(a\)'s grad get written twice. An engine that overwrote instead of accumulating would report only one of the two terms. That exact bug shows up in hand-written backward passes, and in PyTorch when people forget that .grad accumulates across backward() calls unless you zero it.

In matrix form, for a whole layer

For an MLP, the graph's nodes are whole vectors and the chain rule becomes matrix products. Split each layer into its two halves: \(\mathbf{z}^{l} = W^{l}\mathbf{a}^{l-1} + \mathbf{b}^{l}\) (the pre-activation) and \(\mathbf{a}^{l} = \varphi(\mathbf{z}^{l})\) (the activation, the \(\mathbf{h}^l\) from before). Define the error signal \(\boldsymbol\delta^{l} = \partial\mathcal{L}/\partial\mathbf{z}^{l}\). Then:

$$\htmlClass{t1}{\boldsymbol\delta^{l}} = \Big(\big(\htmlClass{t2}{W^{l+1}}\big)^{\!\top}\htmlClass{t1}{\boldsymbol\delta^{l+1}}\Big) \odot \htmlClass{t3}{\varphi'(\mathbf{z}^{l})}, \qquad \frac{\partial \mathcal{L}}{\partial \htmlClass{t2}{W^{l}}} = \htmlClass{t1}{\boldsymbol\delta^{l}}\,\big(\htmlClass{t4}{\mathbf{a}^{l-1}}\big)^{\!\top}, \qquad \frac{\partial \mathcal{L}}{\partial \htmlClass{t5}{\mathbf{b}^{l}}} = \htmlClass{t1}{\boldsymbol\delta^{l}}$$
\(\boldsymbol\delta^{l}\)
gradient of the loss with respect to layer \(l\)'s pre-activations, length \(d_l\)
\(W\)
weight matrices. Going backwards uses the transpose, which maps \(d_{l+1}\) numbers back to \(d_l\)
\(\varphi'(\mathbf{z}^{l})\)
activation derivative, elementwise; \(\odot\) multiplies entry by entry
\(\mathbf{a}^{l-1}\)
the layer's input, saved from the forward pass
\(\mathbf{b}^{l}\)
bias: its gradient is just the error signal

In wordsThe error at a layer is the error from the layer above, sent back through the transposed weights, then gated by how strongly each unit was responding. A weight's gradient is (error at its output) × (value at its input), an outer product, which has exactly the shape of \(W^l\): \(d_l \times d_{l-1}\).

Why it mattersEach layer's backward pass is two matmuls the size of its forward matmul: one for \(\boldsymbol\delta\), one for \(\partial\mathcal{L}/\partial W\). So backward costs about 2× forward, and a training step about 3×. That is where the \(6ND\) training-FLOPs rule in Module 07 comes from (2 FLOPs per parameter per token forward, 4 backward).

With a batch, \(\boldsymbol\delta\) becomes a matrix \(\Delta^l\) of shape \([B, d_l]\) and the weight gradient is \((\Delta^l)^{\top}A^{l-1}\), which sums the per-example outer products over the batch. Nothing else changes.

MLE angle · why training eats memory

The formula needs \(\mathbf{a}^{l-1}\) and \(\mathbf{z}^{l}\) from the forward pass, so every layer's activations must be kept until the backward pass reaches it. For an LLM that is batch × sequence × hidden × layers × several tensors per layer, which is often more than the weights themselves. Activation checkpointing (torch.utils.checkpoint) throws most of them away and recomputes them during the backward pass: roughly a third more compute in exchange for a large cut in memory. Inference never runs a backward pass, so it never stores any of this (Module 07).

Vanishing and exploding gradients

Look at the recursion again: each step backwards multiplies by \((W^{l+1})^{\top}\) and by \(\varphi'\). Unroll it from the loss to the first layer and the gradient reaching the input is a product of one factor per layer. Products of many numbers either shrink towards zero or blow up, unless each factor sits very close to 1.

$$\frac{\partial \mathcal{L}}{\partial \htmlClass{t1}{\mathbf{a}^{0}}} = \Big(\prod_{l=1}^{\htmlClass{t4}{L}} \big(\htmlClass{t2}{W^{l}}\big)^{\!\top} \mathrm{diag}\big(\htmlClass{t3}{\varphi'(\mathbf{z}^{l})}\big)\Big)\,\frac{\partial \mathcal{L}}{\partial \mathbf{a}^{L}} \qquad\Rightarrow\qquad \Big\lVert \frac{\partial \mathcal{L}}{\partial \htmlClass{t1}{\mathbf{a}^{0}}}\Big\rVert \approx \htmlClass{t5}{\gamma}^{\htmlClass{t4}{L}}\,\Big\lVert\frac{\partial \mathcal{L}}{\partial \mathbf{a}^{L}}\Big\rVert$$
\(\mathbf{a}^{0}\)
the input end of the network (the first layers are the ones that starve)
\(W^{l}\)
weights of layer \(l\); their scale sets how much each matmul stretches the signal
\(\varphi'(\mathbf{z}^{l})\)
activation slopes at layer \(l\): at most 0.25 for sigmoid, 0 or 1 for ReLU
\(L\)
depth: the number of factors in the product (taken in order \(l = 1 \ldots L\))
\(\gamma\)
typical per-layer gain: how much one layer scales the gradient's size

In wordsThe gradient reaching layer 1 is the top gradient times one stretch factor per layer. At 50 layers, \(\gamma = 0.9\) leaves you \(0.9^{50} \approx 0.005\) of the signal; \(\gamma = 1.1\) multiplies it by \(1.1^{50} \approx 117\).

Why it mattersVanishing means the early layers stop learning while the late ones train. Exploding means a single step can throw the weights to garbage (loss suddenly spikes to NaN). Hochreiter (1991) and Bengio et al. (1994) identified this in recurrent networks, which are deep in time.

The widget runs a real 64-wide network: random weights with standard deviation \(g/\sqrt{64}\), a forward pass, then a backward pass from a random top gradient. Things to try: sigmoid at any gain (it dies, its slope is too small); tanh at \(g=1\) (slow decay); ReLU at \(g=1\) (loses about half the signal power per layer) against ReLU at \(g=\sqrt{2}\approx1.41\) (flat). The next two sections explain why \(\sqrt 2\) is the magic number, and the residual switch previews the fix that made 100-layer networks trainable.

MLE angle · gradient clipping

Even well-initialized LLMs hit occasional bad batches that produce a huge gradient. Nearly every LLM training recipe rescales the whole gradient vector when its norm exceeds a threshold, typically 1.0: torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0), called between backward() and step(). Log the pre-clip norm. A gradient norm that trends upward over a run is an early warning of instability.

Initialization

If the per-layer gain \(\gamma\) must stay near 1, the starting weights are not a detail. Too small and the signal fades layer by layer; too large and it explodes. The fix is to pick the weight variance so that each layer passes on its input's variance unchanged, in both the forward and the backward direction.

$$\mathrm{Var}(\htmlClass{t1}{z_j}) = \htmlClass{t2}{n_{\text{in}}}\;\mathrm{Var}(\htmlClass{t3}{w})\;\mathbb{E}\big[\htmlClass{t4}{a_i}^{2}\big]$$
\(z_j\)
one pre-activation: \(z_j = \sum_i w_{ji} a_i\)
\(n_{\text{in}}\)
fan-in: how many inputs each neuron sums
\(w\)
weights, drawn independently with mean 0
\(a_i\)
the layer's inputs (the previous layer's activations)

In wordsSumming \(n_{\text{in}}\) independent zero-mean terms adds their variances. So each layer multiplies the signal's size by \(n_{\text{in}}\mathrm{Var}(w)\), adjusted for what the activation does. Make that product 1 and the signal neither grows nor shrinks.

Why it mattersThe backward pass obeys the same rule with fan-out \(n_{\text{out}}\) in place of fan-in. Both initialization schemes below are this one equation solved for \(\mathrm{Var}(w)\).

$$\mathrm{Var}(\htmlClass{t1}{W}) = \frac{2}{\htmlClass{t2}{n_{\text{in}}} + \htmlClass{t3}{n_{\text{out}}}}, \qquad \htmlClass{t1}{W} \sim \mathcal{U}\!\left(-\sqrt{\tfrac{6}{\htmlClass{t2}{n_{\text{in}}}+\htmlClass{t3}{n_{\text{out}}}}},\ \sqrt{\tfrac{6}{\htmlClass{t2}{n_{\text{in}}}+\htmlClass{t3}{n_{\text{out}}}}}\right)$$
\(W\)
the layer's weights, drawn independently (normal or uniform with this variance)
\(n_{\text{in}}\)
fan-in: keeps the forward signal steady
\(n_{\text{out}}\)
fan-out: keeps the backward gradient steady

In wordsThe forward pass wants \(\mathrm{Var}(W) = 1/n_{\text{in}}\), the backward pass wants \(1/n_{\text{out}}\). Glorot and Bengio (2010) split the difference with the harmonic mean. It assumes an activation that acts like the identity near zero, such as tanh.

$$\mathrm{Var}(\htmlClass{t1}{W}) = \frac{\htmlClass{t3}{2}}{\htmlClass{t2}{n_{\text{in}}}}, \qquad \htmlClass{t4}{\sigma_W} = \sqrt{\frac{\htmlClass{t3}{2}}{\htmlClass{t2}{n_{\text{in}}}}}$$
\(W\)
weights of a layer followed by ReLU
\(n_{\text{in}}\)
fan-in
2
compensates for ReLU zeroing half its inputs: \(\mathbb{E}[\mathrm{ReLU}(z)^2] = \tfrac12\mathrm{Var}(z)\) for symmetric \(z\)
\(\sigma_W\)
the standard deviation you actually pass to the random generator

In wordsReLU throws away half the signal power, so start the weights \(\sqrt 2\) larger to put it back (He et al., 2015). For a 4096-wide layer: \(\sigma_W = \sqrt{2/4096} \approx 0.0221\).

Why it mattersThis is the \(g = \sqrt 2\) setting in the widget above, where the ReLU curve goes flat across 100 layers. PyTorch's torch.nn.init.calculate_gain returns these factors: \(\sqrt 2\) for ReLU, \(5/3\) for tanh.

Think first: what goes wrong if you initialize every weight to zero?
With tanh, every hidden activation is \(\tanh(0) = 0\), so every weight gradient \(\boldsymbol\delta\,\mathbf{a}^{\top}\) into the next layer is 0, and every \(\boldsymbol\delta\) sent backwards through the zero weights is also 0. Only the output bias learns. Initializing to any equal nonzero constant is a subtler version of the same failure: every unit in a layer computes the same thing and receives the same gradient, so they stay clones forever. Random initialization exists to break that symmetry, and the variance rules above tell you how big "random" should be.
WhereDefault weight initStd for fan-in 4096

The PyTorch default is smaller than He, and deep plain ReLU stacks built with bare nn.Linear do lose signal. Transformers get away with simple fixed-std schemes because the next two ideas, normalization and residual connections, keep the signal in range regardless.

Normalization

Good initialization sets the scale at step 0, but the weights move during training and the activations drift with them. Normalization layers re-standardize the activations on every forward pass: subtract a mean, divide by a standard deviation, then let two learned vectors put back whatever scale and offset the network actually wants. The two main variants differ only in which numbers they average over.

$$\htmlClass{t1}{\hat x_{b,t,j}} = \frac{x_{b,t,j} - \htmlClass{t2}{\mu_j}}{\sqrt{\htmlClass{t3}{\sigma_j^2} + \epsilon}}, \qquad \htmlClass{t2}{\mu_j} = \frac{1}{BT}\sum_{b,t} x_{b,t,j}, \qquad y_{b,t,j} = \htmlClass{t4}{\gamma_j}\,\htmlClass{t1}{\hat x_{b,t,j}} + \htmlClass{t5}{\beta_j}$$
\(\hat x_{b,t,j}\)
normalized activation of feature \(j\) at sequence \(b\), position \(t\)
\(\mu_j\)
mean of feature \(j\) across every example and position in the batch
\(\sigma_j^2\)
variance of feature \(j\) across the same set
\(\gamma_j\)
learned per-feature scale
\(\beta_j\)
learned per-feature shift

In wordsFor each feature, standardize it using statistics from the whole batch (Ioffe & Szegedy, 2015). At inference there may be no batch, so BatchNorm switches to running averages collected during training.

$$\htmlClass{t1}{\hat x_{j}} = \frac{x_{j} - \htmlClass{t2}{\mu}}{\sqrt{\htmlClass{t3}{\sigma^2} + \epsilon}}, \quad \htmlClass{t2}{\mu} = \frac{1}{d}\sum_{k=1}^{d} x_{k}, \quad y_j = \htmlClass{t4}{\gamma_j}\,\htmlClass{t1}{\hat x_j} + \htmlClass{t5}{\beta_j} \qquad\quad \htmlClass{t6}{\mathrm{RMSNorm}}(\mathbf{x})_j = \frac{x_j}{\sqrt{\frac{1}{d}\sum_k x_k^2 + \epsilon}}\;\htmlClass{t4}{\gamma_j}$$
\(\hat x_j\)
normalized feature \(j\) of one token's vector
\(\mu\)
mean over that token's \(d\) features
\(\sigma^2\)
variance over that token's \(d\) features
\(\gamma_j\)
learned per-feature scale
\(\beta_j\)
learned per-feature shift (RMSNorm drops it)
RMSNorm
skips the mean subtraction and only divides by the root-mean-square (Zhang & Sennrich, 2019). Used by Llama, Qwen, Mistral

In wordsLayerNorm standardizes each token's vector using only that vector's own numbers (Ba et al., 2016). Nothing depends on the rest of the batch, so training and inference behave identically, even at batch size 1.

Why it mattersLanguage models decode one token at a time with arbitrary batch sizes and padded sequences of different lengths. Statistics that mix sequences would make one user's output depend on another's prompt. Per-token normalization avoids that, and RMSNorm is a little cheaper with no measurable loss in practice.

Residual connections

Here's the trick that made very deep networks routine. Instead of each block replacing its input, let it add a correction to it. He et al. (2016) used this to train 152-layer ResNets, and every transformer is built this way: each attention and MLP block writes into a shared "residual stream" (Module 06).

$$\htmlClass{t1}{\mathbf{x}_{l+1}} = \htmlClass{t2}{\mathbf{x}_{l}} + \htmlClass{t3}{F_l}(\htmlClass{t2}{\mathbf{x}_{l}}), \qquad \frac{\partial \htmlClass{t1}{\mathbf{x}_{l+1}}}{\partial \htmlClass{t2}{\mathbf{x}_{l}}} = \htmlClass{t4}{I} + \frac{\partial \htmlClass{t3}{F_l}}{\partial \htmlClass{t2}{\mathbf{x}_l}}$$
\(\mathbf{x}_{l+1}\)
output of block \(l\)
\(\mathbf{x}_{l}\)
input of block \(l\), carried through unchanged by the skip connection
\(F_l\)
the block's learned transformation: an MLP, or norm + attention in a transformer
\(I\)
identity matrix: the derivative of the skip path, exactly 1 in every direction

In wordsThe block only has to learn what to change, and if it learns nothing, the input passes straight through. On the way back, the gradient gets the identity term for free, so it can't be multiplied away to nothing by a long chain of small factors.

Why it mattersUnrolled, \(\mathbf{x}_L = \mathbf{x}_0 + \sum_l F_l(\mathbf{x}_l)\). The gradient at \(\mathbf{x}_0\) contains \(\partial\mathcal{L}/\partial\mathbf{x}_L\) directly, plus correction terms. Flip the residual switch in the vanishing-gradient widget and the 100-layer sigmoid network trains its first layer again.

Intuition

A plain deep network is a game of telephone: each layer must faithfully relay the message, and errors compound. A residual network is a shared document where each layer adds a margin note. Even if one layer writes nonsense, the original text is still there for the next layer to read, and the feedback (the gradient) reaches every author directly.

Regularization

A network with enough parameters can memorize its training set, noise included, and then do badly on new data. That's overfitting: training loss keeps falling while held-out loss turns upward. Regularization is anything that makes memorization harder than learning the general pattern. Two techniques show up in almost every codebase.

Definition · dropout

During training, zero each activation independently with probability \(p\), and scale the survivors by \(1/(1-p)\): \(\tilde{\mathbf{h}} = \mathbf{m}\odot\mathbf{h}/(1-p)\), with \(m_i \sim \mathrm{Bernoulli}(1-p)\) (Srivastava et al., 2014). The scaling keeps the expected value unchanged, so at evaluation time dropout is simply switched off with no rescaling. This is "inverted dropout" and is what nn.Dropout does. It stops units from relying on specific partners, a bit like training an ensemble of thinned networks that share weights. It's also the reason model.eval() matters: forget it and inference stays random.

Definition · weight decay

Shrink every weight a little at every step: \(\mathbf{w} \leftarrow \mathbf{w} - \eta\,(\nabla_{\mathbf{w}}\mathcal{L} + \lambda\mathbf{w})\). For plain SGD this is the same as adding an L2 penalty \(\tfrac{\lambda}{2}\lVert\mathbf{w}\rVert^2\) to the loss. For Adam it isn't, because Adam rescales the penalty's gradient along with everything else. AdamW (Loshchilov & Hutter, 2019) fixes this by applying the \(\lambda\mathbf{w}\) shrink outside the adaptive scaling. PyTorch's torch.optim.AdamW multiplies the weights by \((1 - \eta\lambda)\) before each Adam update.

MLE angle · what LLMs actually use

Large-scale pretraining usually sees each token roughly once, so classic overfitting is rare. Many recent recipes set dropout to 0 and rely on AdamW with weight decay around 0.1 (the value reported for GPT-3 and Llama 2), typically skipping decay on biases and norm gains. Dropout returns in fine-tuning, where the dataset is small: LoRA configs commonly carry lora_dropout=0.05 (Module 10). Held-out loss and early stopping remain the most important regularizers for small datasets.

1. A scalar autograd engine (micrograd-style)

This is Karpathy's micrograd idea in under 50 lines. Each Value records its parents and a closure that knows its local derivative; backward() sorts the graph topologically and calls those closures in reverse. The final line reproduces the default graph in the step-through widget.


import math

class Value:
    """A scalar that remembers how it was computed, so it can backprop."""
    def __init__(self, data, _children=(), _op=""):
        self.data = data
        self.grad = 0.0
        self._backward = lambda: None
        self._prev = set(_children)
        self._op = _op

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad += out.grad                  # d(x+y)/dx = 1
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():
            self.grad += other.data * out.grad     # d(xy)/dx = y
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,), "tanh")
        def _backward():
            self.grad += (1 - t * t) * out.grad    # d tanh(x)/dx = 1 - tanh^2
        out._backward = _backward
        return out

    __radd__ = __add__
    __rmul__ = __mul__
    def __neg__(self): return self * -1
    def __sub__(self, other): return self + (-other)

    def backward(self):
        topo, seen = [], set()
        def build(v):
            if v not in seen:
                seen.add(v)
                for child in v._prev:
                    build(child)
                topo.append(v)                     # children before parents
        build(self)
        self.grad = 1.0
        for v in reversed(topo):
            v._backward()

a, b, c, f = Value(2.0), Value(-3.0), Value(10.0), Value(-2.0)
L = (a * b + c) * f
L.backward()
print(L.data, a.grad, b.grad, c.grad, f.grad)      # -8.0 6.0 -4.0 -2.0 4.0

2. The same MLP in PyTorch

The widget's network, as an nn.Module with the standard training loop. loss.backward() runs exactly the backward pass you stepped through above, on every weight at once.


import math
import torch
import torch.nn as nn
import torch.nn.functional as F

def two_moons(n=400, noise=0.1, seed=0):
    g = torch.Generator().manual_seed(seed)
    t = torch.rand(n // 2, generator=g) * math.pi
    outer = torch.stack([torch.cos(t), torch.sin(t)], dim=1)
    inner = torch.stack([1 - torch.cos(t), 0.5 - torch.sin(t)], dim=1)
    X = torch.cat([outer, inner]) + noise * torch.randn(n, 2, generator=g)
    y = torch.cat([torch.zeros(n // 2), torch.ones(n // 2)])
    return X, y

class MLP(nn.Module):
    def __init__(self, d_in=2, hidden=16, d_out=1):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(d_in, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, d_out),              # no activation: output is a logit
        )
        for m in self.net:
            if isinstance(m, nn.Linear):
                nn.init.xavier_normal_(m.weight)   # Glorot, suits tanh
                nn.init.zeros_(m.bias)

    def forward(self, x):
        return self.net(x).squeeze(-1)             # [B, 1] -> [B]

torch.manual_seed(0)
X, y = two_moons()
X_test, y_test = two_moons(seed=1)
model = MLP()
opt = torch.optim.AdamW(model.parameters(), lr=2e-2, weight_decay=1e-4)

for step in range(2001):
    model.train()
    logits = model(X)                              # forward: full batch
    loss = F.binary_cross_entropy_with_logits(logits, y)
    opt.zero_grad(set_to_none=True)                # grads accumulate otherwise
    loss.backward()                                # backprop: fills p.grad for every parameter
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step()                                     # AdamW update
    if step % 250 == 0:
        model.eval()
        with torch.no_grad():
            acc = ((model(X_test) > 0).float() == y_test).float().mean().item()
        print(f"step {step:4d}  train loss {loss.item():.4f}  test acc {acc:.3f}")

You stack ten nn.Linear layers with no activation functions between them. Which functions can this network represent?

  1. Any continuous function, given enough width
  2. Only affine functions \(A\mathbf{x} + \mathbf{b}\), exactly what a single layer can represent
  3. Piecewise-linear functions with up to ten kinks
  4. Polynomials up to degree ten
A composition of affine maps is affine: \(W_2(W_1\mathbf{x}+\mathbf{b}_1)+\mathbf{b}_2 = (W_2W_1)\mathbf{x} + (W_2\mathbf{b}_1+\mathbf{b}_2)\). Depth adds parameters but no expressive power until a nonlinearity sits between the layers.

\(L = (a\cdot b + c)\cdot f\) with \(a = 1,\ b = 4,\ c = -2,\ f = 3\). What is \(\partial L/\partial a\)?

  1. 3
  2. 4
  3. 12
  4. 6
Backwards: \(\partial L/\partial d = f = 3\) where \(d = ab + c\). The add passes 3 to \(e = ab\) unchanged. The multiply sends \(a\) the grad times the other input: \(3 \times b = 12\). Check with a nudge: \(a = 1.01\) gives \(L = (4.04 - 2)\cdot 3 = 6.12\), up \(0.12 = 12 \times 0.01\).

A 20-layer MLP uses sigmoid activations everywhere, and its weights are scaled so each matrix alone preserves the gradient's size. In the best case, how does the gradient at layer 1 compare with the gradient at the top?

  1. Roughly \(10^{12}\) times smaller
  2. About 20 times smaller
  3. About 5 times smaller
  4. The same, because the sigmoid's slope is 1 at the origin
\(\sigma'\) is at most 0.25, reached at \(z = 0\). Twenty factors of at most 0.25 give \(0.25^{20} \approx 9\times10^{-13}\). The slope of 1 at the origin belongs to tanh, not sigmoid. This is why sigmoid disappeared from hidden layers.

You He-initialize a ReLU layer with fan-in 4096. What standard deviation do you pass to the random normal generator?

  1. 0.0156
  2. 0.0221
  3. 0.000488
  4. 0.0313
\(\sigma = \sqrt{2/n_{\text{in}}} = \sqrt{2/4096} \approx 0.0221\). 0.0156 is \(\sqrt{1/4096}\) (the Xavier value for a square layer), and 0.000488 is the variance \(2/4096\), a common slip when an API wants a std.

Why do transformers use LayerNorm or RMSNorm instead of BatchNorm?

  1. LayerNorm has fewer learned parameters
  2. Gradients can't flow through BatchNorm
  3. LayerNorm averages over the batch, which is more stable for long sequences
  4. Each token is normalized using only its own features, so behaviour doesn't depend on batch size or on other sequences in the batch
BatchNorm's statistics come from the whole batch, so outputs depend on which other sequences happen to be batched together, and inference has to fall back to running averages. LayerNorm's statistics are per token, identical at training and at batch-1 decode. Both have the same \(\gamma, \beta\) parameter count, and both are differentiable.

A 3-class classifier outputs softmax probabilities \(p = [0.7,\ 0.2,\ 0.1]\). The true class is index 1. What is the gradient of the cross-entropy loss with respect to the logits?

  1. \([0.7,\ -0.8,\ 0.1]\)
  2. \([-0.7,\ 0.8,\ -0.1]\)
  3. \([0,\ -5,\ 0]\)
  4. \([0.7,\ 0.2,\ 0.1]\)
\(\partial\mathcal{L}/\partial z_k = p_k - \mathbb{1}[k=y]\), so subtract 1 from the true class only: \([0.7, 0.2-1, 0.1]\). Gradient descent moves against this, raising the true logit and lowering the others. \([0, -5, 0]\) is the gradient with respect to the probabilities (\(-1/p_y\)), not the logits.

A layer uses nn.Dropout(p=0.1). During training, a unit whose value is 2.0 survives the dropout mask. What does the next layer see in training, and at evaluation time?

  1. 2.0 in training; 1.8 at eval
  2. 1.8 in training; 2.0 at eval
  3. About 2.22 in training; 2.0 at eval, with dropout off
  4. 2.0 in training; about 2.22 at eval
Inverted dropout scales survivors by \(1/(1-p) = 1/0.9\) during training, so the expected value stays at 2.0 (\(0.9 \times 2.22 + 0.1 \times 0\)). At eval the layer is the identity and nothing is rescaled. That only happens if you call model.eval().
